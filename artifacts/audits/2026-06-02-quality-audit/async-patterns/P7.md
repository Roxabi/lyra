### Summary
One P2 race condition (TOCTOU in SqliteStore connection) and six P3 issues (defensive gaps, CPU-bound serialization in hot paths, sync queue bypass). No critical blocking calls, missing awaits, or unreferenced tasks found.

### Findings
| severity | file | line | description |
|---|---|---|---|
| P2 | src/lyra/infrastructure/stores/base/sqlite_base.py | 84-86 | TOCTOU race in `_open_db`: `if self._db is not None` check is non-atomic with `self._db = await aiosqlite.connect(...)`. Concurrent `connect()` calls can create multiple connections, overwriting `self._db` and leaking the earlier ones. Affects all subclasses (AgentStore, TurnStore, BotStore, AuthStore, PrefsStore, IdentityAliasStore, PairingStore, ThreadStore). |
| P3 | src/lyra/nats/nats_channel_proxy.py | 206-210 | `send_streaming` `finally` block only catches `asyncio.CancelledError` when `await keepalive_task`. If `_run_keepalive_loop` raises an unexpected exception (non-`nats.errors.Error`, non-`CancelledError`), `await keepalive_task` will raise it in `finally`, potentially masking the original streaming exception. |
| P3 | src/lyra/nats/nats_channel_proxy.py | 94-95 | `_to_json()` performs synchronous `serialize()` + `json.loads()` + `.decode()` inside async methods (`send`, `send_streaming`, `render_audio`, `render_attachment`). CPU-bound for large payloads; negligible for current envelope sizes but blocks the event loop under high throughput. |
| P3 | src/lyra/nats/nats_bus.py | 255 | `_handle_nats_message` uses `self._staging.put_nowait(item)` instead of `await self._staging.put(item)`. This is intentional drop-on-full behavior, but it bypasses async backpressure and can silently drop messages under load. |
| P3 | src/lyra/transport/worker_pool_client.py | 109 | `_on_heartbeat` calls `json.loads(msg.data.decode("utf-8"))` synchronously inside an async callback. Payloads are small; negligible impact. |
| P3 | src/lyra/infrastructure/stores/turn_store.py | 184 | `_log_turn` calls `json.dumps(metadata or {})` synchronously inside an async DB write path. Small dicts; negligible impact. |
| P3 | src/lyra/infrastructure/blobstore_adapter.py | 104-105 | `aclose()` directly accesses `self._http_store._client` (private attribute) and nulls it. If the store is used concurrently during shutdown, the client could be nulled while another coroutine is mid-request. No external lock protects this. |

### Recommendations (prioritized, with effort estimate)
1. **Fix SqliteStore TOCTOU race** — Add an `asyncio.Lock` around the `_open_db` null-check + connect sequence. Effort: 15 min. Risk: low; standard pattern.
2. **Harden NatsChannelProxy keepalive cleanup** — Wrap `await keepalive_task` in `finally` with a broad `except Exception` (or `try/except Exception` around the `await`) to prevent unexpected task exceptions from escaping the cleanup path. Effort: 5 min.
3. **Offload CPU-bound serialization to executor** — For `_to_json` (nats_channel_proxy), `_handle_nats_message` json.loads (nats_bus), and `_on_heartbeat` json.loads (worker_pool_client), wrap in `asyncio.get_running_loop().run_in_executor(None, ...)` if profiling shows event-loop blocking. Effort: 20 min. Risk: negligible today; defer until profiling confirms.
4. **Document NatsBus drop-on-full behavior** — Add a comment or ADR note that `put_nowait` is intentional and that staging queue full → message drop is the designed backpressure. Effort: 2 min.
5. **Add a shutdown lock to blobstore_adapter** — Protect `aclose()` with a simple `asyncio.Lock` to prevent concurrent `put/get/exists` from racing with the client teardown. Effort: 10 min.
