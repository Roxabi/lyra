## Consensus ρ

### F2 — `else` in guard list

**Remove `else` from the main guard list. Add a separate exception note for `else` branches that encode an error/exceptional path.**

Rationale: `else` is the default path, not a condition to negate. Every `else` in the codebase would require a negative test under the current rule, causing false merge blocks from `dev-core:tester`. The valid case (`else: raise SomeError`, `else: return sentinel`) is real but narrow — it belongs in a separate exception clause, not the main list. LLM agents pattern-match on list items; even a qualified `else` in the list will over-fire.

Architect dissent recorded: preferred qualifying `else` inline as a sub-bullet rather than relocating it. Accepted hybrid: remove from list + add explicit exception note so the `else: raise` case isn't silently exempted.

```
# Before
- `if` / `elif` / `else` branching on a condition

# After
- `if` / `elif` branching on a condition
- `else` branches that encode a distinct error or exceptional path (e.g., `else: raise ValueError(...)`) — not general fallthrough or happy-path defaults
```

### F3 — Missing cross-reference to architecture-patterns.md

**Add one cross-reference line at the end of the Test Trophy section.**

Rationale: The Trophy section (priority order) and the Testing Strategy table in `architecture-patterns.md` (layer-to-tool mapping) answer different questions and should coexist. No merge. Risk of drift without a cross-reference is real. Cost of one line is zero.

```
> Layer-to-tool mapping: see [Architecture Patterns — Testing Strategy](architecture-patterns.md#testing-strategy).
```

### F4 — Nav meta.json

Rationale: `stack.yml docs.framework: none` — no sidebar consumer exists. The `meta.json` in `docs/architecture/adr/` is an ADR skill registry, not a nav file. Adding `docs/architecture/meta.json` today is dead config. Revisit when a docs framework is adopted.
