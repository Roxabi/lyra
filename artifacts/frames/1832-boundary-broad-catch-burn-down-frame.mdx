## Problem

ADR-073 revisit trigger `boundary-broad-catch ≤ 30` is officially tripped. Phase 7 (#1284)
closed 2026-05-31, activating the post-epic target. Mickael validated on 2026-06-11: **burn
down, not re-baseline**.

Measured at issue filing (2026-06-10): **150** `except Exception` sites across **91** files in
`src/factory/`. Re-measured 2026-06-24 on staging: **168 sites / 102 files** — the debt has
**grown** (+12%) as new features landed (#1812 OmpWorker, #1946 KV roster, Telegram Rich
Messages, #1931 adapter glue kit) with no burn-down slice started.

Of 168 sites: **57** carry `DEBT:boundary-broad-catch`; **50** additional BLE001 suppressions
in `src/factory/` are **untagged** (invisible to the debt ratchet). Many adapter/blobstore
sites are expected HTTP/NATS boundaries (ADR-067/082) but lack inline POLICY justification.

The N×M risk is concentrated in `core/` (47 sites, especially `pool/` ×15 and `hub/` ×9)
and `infrastructure/stores/` (21 sites): broad catches there can hide stage-boundary
violations — the anti-pattern ADR-073 was written to eliminate.

Observable impact: axial health metric is ×5–×6 the committed target; contributors adding
features continue to introduce untagged broad catches; the revisit trigger is acknowledged but
unaddressed.

## Premise Validity

**Success in 6 months:** `grep -r 'except Exception' src/factory/ --include='*.py' | wc -l`
returns ≤ 30; every remaining site has inline justification (DEBT drained or POLICY/boundary
acknowledged); ADR-073 revisit-trigger section documents the new steady-state; zero untagged
BLE001 in `src/factory/`; no increase in sibling-fix rate on stage concerns.

**Failure in 6 months:** Site count remains ≥ 150 (or rises) after three burn-down sprint
cycles; untagged BLE001 count stays ≥ 40; `core/pool/` and `core/hub/` broad catches
unchanged; ADR-073 6-monthly review (2026-11-01) surfaces the same trigger with no
documented steady-state — observable via grep count + git log of `except Exception` diffs.

**Simplest alternative:** Tag-first pass only — classify all 50 untagged sites as
`DEBT:boundary-broad-catch` or `POLICY:boundary-broad-catch`, reclassify adapters/blobstore
HTTP catches as acknowledged boundaries, update ADR baseline note, close issue when tagged
count ≤ 30.

**Why not simplest:** Tagging reduces report noise but does not fix the N×M axial risk in
`core/pool/` (15 sites) and `core/hub/` (9 sites) where broad catches mask stage-boundary
violations. The revisit trigger measures residual axis drift, not annotation compliance —
bookkeeping without narrowing leaves the underlying failure mode intact.
