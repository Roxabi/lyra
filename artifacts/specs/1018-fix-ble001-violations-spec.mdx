## Context

Promoted from: `artifacts/analyses/1018-fix-ble001-violations-analysis.mdx`
Frame: `artifacts/frames/1018-fix-ble001-violations-frame.mdx`

121 blind `except Exception:` catches across 67 files. Ruff BLE001 cannot be enabled as a quality
gate until zero violations remain. Violations fall into 4 structurally distinct categories
requiring different fix strategies.

## Goal

`uv run ruff check --select BLE001 .` returns zero violations, with BLE001 added to the default
`[tool.ruff.lint] select` list in `pyproject.toml`, and no file-level blanket noqa anywhere.

## Users

- **Maintainers** — broad catches currently hide runtime failures during debugging and incident response
- **CI** — BLE001 quality gate unblocked; future violations caught on first push

## Expected Behavior

After this change, every `except` clause in the codebase that previously caught `Exception` blindly
either:
1. Catches a specific, narrower exception type (categories A, D, Special)
2. Catches a library-specific base exception (`nats.errors.Error`, `discord.HTTPException`, `TelegramError`)
3. Retains `except Exception` with an inline `# noqa: BLE001  # <reason>` comment that explains
   in one sentence why broad catching is intentional

Category C (error boundaries) additionally must have `log.exception(…)` or `exc_info=True` in
every catch body — no silent swallows. Where that line is missing, it is added before the noqa.

The final commit adds `BLE001` to `[tool.ruff.lint] select` in `pyproject.toml`. Running ruff
confirms zero violations. Existing tests all pass.

### Exception type decision table

| Context | Preferred replacement | Fallback |
|---------|----------------------|----------|
| `json.loads()` | `(json.JSONDecodeError, ValueError)` | — |
| `tomllib.load()` | `(tomllib.TOMLDecodeError, OSError)` | — |
| Custom deserialize fn (`_deserialize_dict`) | `(ValueError, TypeError)` | — |
| `str.format_map()` | `(KeyError, ValueError)` | — |
| `get_type_hints()` | noqa — can raise `NameError`/`AttributeError`/`RecursionError` from user types | — |
| NATS publish/subscribe/unsubscribe | `nats.errors.Error` | — |
| NATS JS purge in tests | `nats.js.errors.NotFoundError` | — |
| NATS retry-loop (isinstance pattern) | `(nats.errors.Error, TimeoutError)` | — |
| Discord API send | `discord.HTTPException` | `discord.DiscordException` at boundaries |
| Discord attachment read | `(discord.HTTPException, OSError)` | — |
| Telegram API send | `TelegramError` (aiogram) | — |
| ContextVar.get() | `LookupError` (theoretically unreachable) | — |
| Logging filter (must never raise) | noqa `# logging filter: must never raise` | — |
| SQLite teardown | noqa `# db teardown` | — |
| Streaming edit (fire-and-forget UI) | noqa `# streaming edit: any send failure is non-fatal` | — |
| Top-level process boundary (sys.exit path) | noqa `# top-level boundary: process exits on error` | — |
| Top-level middleware/pool boundary | noqa `# top-level boundary` (requires `exc_info=True`) | — |
| Test error capture (catch IS the test) | noqa `# test error capture: any error is the test subject` | — |
| Test teardown | noqa `# test teardown` | — |
