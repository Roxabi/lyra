### Summary
Partition P8 (LLM, agents, stages, misc) shows solid security hygiene: no secrets in code, no `eval`/`exec`/`pickle`/`shell=True`, parameterized SQL throughout, and `hmac.compare_digest` for bearer auth. Four issues remain: two medium input-validation gaps in monitoring escalation and two low-severity hygiene gaps.

### Findings
| severity | file | line | description |
|---|------|------|-------------|
| P2 | `src/lyra/monitoring/escalation.py` | 49 | `_parse_diagnosis` calls `json.loads(text)` on LLM-generated output without error handling or schema validation. Missing keys (`diagnosis`, `suggested_remediation`) raise `KeyError` that propagates uncaught, causing Layer 2 escalation to fail. |
| P2 | `src/lyra/monitoring/escalation.py` | 75 | `_escalate_via_cli` constructs a prompt from `report` data (which includes HTTP health endpoint responses and `str(exc)` strings) and passes it via `-p` to the `claude` CLI. If the health endpoint is compromised, this is a prompt injection vector. |
| P3 | `src/lyra/monitoring/config.py` | 40 | `health_secret: str = ""` lacks `repr=False`, unlike `telegram_token` and `telegram_admin_chat_id` on the same model. If the config object is logged or repr'd, the Bearer token leaks. |
| P3 | `src/lyra/integrations/vault_cli.py` | 67 | `title` is passed as a CLI argument without `_SAFE_CLI_ARG_RE` validation (only `category` and `entry_type` are validated). While `create_subprocess_exec` prevents shell injection, a malformed `title` could be misinterpreted by the downstream `vault` CLI parser. |

### Clean patterns verified
- **No hardcoded secrets** — all tokens/passwords loaded from env vars or secret mounts.
- **No unsafe execution** — zero occurrences of `eval`, `exec`, `compile`, `pickle`, `marshal`, `yaml.load`, `os.system`, or `shell=True` in the 70 audited files.
- **SQL injection safe** — all SQLite queries in `blobstore/` use `?` placeholders (`_keys.py`, `_handlers.py`, `serve.py`).
- **Bearer auth correct** — `blobstore/auth.py:74` uses `hmac.compare_digest` (not `==`).
- **Subprocess discipline** — all subprocess calls use `asyncio.create_subprocess_exec` or `subprocess.run` with list arguments (no shell). `vault_cli.py` uses `--` to end option parsing before `body`.
- **Token isolation** — `gh_token/` helper runs as uid 1501, tmpfs 0700, cache 0600, socket 0660. Token never enters uid 1500 env.
