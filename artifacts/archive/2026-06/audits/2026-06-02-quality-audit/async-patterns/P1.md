### Summary
Partition P1 (Hub, lifecycle, ports) is generally clean: no `time.sleep`, no blocking HTTP calls, no unawaited coroutines, and all `asyncio.create_task` calls store task references. Two issues found: a race condition in `OutboundDispatcher` scope-lock reaping (P2) and `threading.Lock` held inside async paths in `PoolManager` (P2). Several `create_task` calls lack `name=` for debugging (P3).

### Recommendations (prioritized)

1. **Fix `_reap_scope_locks` race condition** (P2, effort: S)
   - In `outbound_dispatcher.py:208`, do not reap locks that have a pending task in `_scope_tasks`. One approach: before reaping, check if any task in `_scope_tasks` is not done and references the scope via `task.get_name()`. Or switch to a WeakValueDictionary and let the lock be garbage-collected when no task holds it.

2. **Replace `threading.Lock` with `asyncio.Lock` in `PoolManager`** (P2, effort: M)
   - In `pool_manager.py:33`, switch to `asyncio.Lock()`. This requires changing `get_or_create_pool()` and `pools` from sync to async, which ripples into `MessagePrepMiddleware` and `HubPoolDelegationMixin`. Alternatively, keep the hybrid model but move the `_sync_evict_entry()` call and `asyncio.create_task()` outside the lock so the lock is held only for dict operations.

3. **Add `name=` to all `asyncio.create_task` calls** (P3, effort: XS)
   - Add `name=f"..."` to the 7 unnamed `create_task` calls across `outbound_dispatcher.py`, `pool_manager.py`, `hub_shutdown.py`, `session_lifecycle.py`, and `outbound_tts.py`. Improves debugging in `asyncio.all_tasks()` and trace logs.

4. **Offload `json.loads` to thread pool** (P3, effort: XS)
   - In `session_lifecycle.py:128,166`, wrap `json.loads` with `asyncio.to_thread()` or `loop.run_in_executor()` to keep the async loop fully non-blocking. Inputs are small, so the risk is low; the fix is a one-line change.
