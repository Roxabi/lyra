## Context

Promoted from [frame #1591](../frames/1591-refactor-emitter-stage-extraction-frame.mdx).

`src/lyra/outbound/emitter.py` is 474 lines. Previous extractions (`_tool_recap.py`, `_streaming_state.py`, `throttle.py`) already reduced the original bulk. The remaining overweight is concentrated in two self-contained subsystems:

1. **Placeholder lifecycle** (`_send_placeholder`, `_drain_fallback`, `_deliver_text_chunks`, `_deliver_final`, `_handle_typing_tail`) — creation, debounced edits, final delivery, overflow handling, and error fallback.
2. **Run-loop orchestration** (`run`, `_run_event_loop`) — the high-level event-loop driver that ties the lifecycle together.

Both subsystems can be extracted into their own modules without changing the external `OutboundEmitter` contract.

## Goal

`emitter.py` < 300 lines after extraction, with all extracted logic living in focused sibling modules under `src/lyra/outbound/`.

## Users

- **Primary:** lyra maintainers (outbound stage readability, file-length gate compliance)
- **Secondary:** Future contributors (smaller files → faster onboarding, clearer boundaries)

## Expected Behavior

After extraction, the `OutboundEmitter` class retains only:
- Constructor (`__init__`)
- Public method `run()` (or a thin delegate to the extracted run-loop)
- Stage-composition wiring (tool_display_config, _tool_recap, _st, _fmt, _handler, _typing)
- Event-dispatch helpers (`_on_text_v2`, `_on_toolcall_v2`, `_ensure_trace_obj`, `_maybe_emit_intermediate_recap`, `_cancel_typing`, `_start_typing`)

All extracted methods continue to operate on the same `OutboundEmitter` instance — they become free functions or a helper class that receives `self` as a parameter. The public API and call graph remain unchanged from the consumer perspective.
