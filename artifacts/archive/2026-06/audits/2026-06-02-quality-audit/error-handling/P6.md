### Summary
Partition P6 (bootstrap + plugin commands) has one critical swallowed-error in store migration and several broad-catch / missing-logging patterns in lifecycle shutdown and command handlers. The plugin command handlers for `identity`, `search`, and `pairing` violate the documented "never raise" contract by calling store methods without boundary catches.

### Recommendations
1. **bootstrap_stores.py:62** — Add `as exc` and `log.warning("Migration check failed: %s", exc)` before returning `False`, so operators can distinguish "not migrated" from "DB broken". (P1)
2. **bootstrap_stores.py:148** — Add `log.debug("Index creation skipped: %s", exc)` inside the except block, or narrow the catch to `sqlite3.OperationalError` with a specific message check for "already exists". (P2)
3. **audio_consumer_bootstrap.py:108** — Narrow to specific expected exceptions (e.g., `NatsError`, `OSError`) instead of `Exception`. If a programming bug raises `TypeError`, it should crash loudly, not silently degrade. (P2)
4. **bootstrap_lifecycle.py:96 & lifecycle_helpers.py:109** — After `gather(return_exceptions=True)`, iterate results and log any non-`CancelledError` exceptions at `warning` level. (P2)
5. **Plugin commands** — Wrap store calls in `try/except` and return `safe_error_response` or a user-friendly `Response`. The command router should not be the only safety net. (P2)
6. **P3 gathers** — Apply the same post-gather logging pattern to `standalone_telegram.py:79`, `standalone_discord.py:111`, and `factory/unified.py:116`. (P3)
