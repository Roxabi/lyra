## Problem

On 2026-05-26 00:00, M₁'s `lyra-telegram` and `lyra-discord` adapters entered a crash-loop (1446 NRestarts in 6.5 h) with `MissingCredentialsError: missing token at /run/secrets/bot_token-lyra`. The Podman secret store on M₁ held all 4 bot-token secrets intact (`lyra-bot-{telegram,discord}-{lyra,aryl}`); what was missing was the `Secret=…,target=bot_token-…` directives in the live Quadlet unit files at `~/.config/containers/systemd/lyra-{telegram,discord}.container`.

Root cause: those per-bot `Secret=` lines live inside a `# --- BEGIN bot secrets --- … # --- END bot secrets ---` block in the Quadlet. The repo-tracked template carries only a `# Secret=…-demo` placeholder; the *real* lines (rendered by `make quadlet-bot-secrets-render` into `.bot-secrets.*.fragment` files on May 22) must be manually spliced into the local file by an operator. The splice is uncommitted by design — bot enumeration is per-host. During the #1331 incident on 2026-05-25 17:54, `make deploy` ran `git pull --ff-only origin staging`, which fast-forwarded the local file (no conflict — there was no upstream change to the block), discarding M₁'s splice. `make quadlet-install` then copied the stub to `~/.config/containers/systemd/`. Adapters kept running on the cached prior unit until the next restart at 00:00 — then they couldn't see the secret mounts and crash-looped.

**Cascade class.** Same pattern as #1361 (NATS-seed cascade fixed in #1363): operator-local mutations to git-tracked files silently overwritten by `git pull --ff-only`. The hotfix applied 2026-05-26 00:21 (re-splice from fragment files) is fragile — the next `git pull` on M₁ wipes it again.

## Who

- **Primary:** Mickael (sole operator) — deploys to M₁ via `make deploy` / `make full-deploy`. Pays the recovery cost when adapters crash-loop (manual diagnosis + hotfix re-splice).
- **Secondary:** End users on Telegram/Discord — `lyra` and `aryl` bots become unreachable for the duration of the crash-loop until the splice is restored.

## Constraints

- **Backwards-compatible with current `lyra bot secret install <platform> <bot_id>` flow** — the Podman secret naming convention (`lyra-bot-<platform>-<bot_id>` → mount target `bot_token-<bot_id>`) must remain. Adapter code in `src/lyra/bootstrap/credentials.py` reads `/run/secrets/bot_token-<bot_id>` — no app-side changes.
- **Rootless Podman on M₁** — render must work as user `mickael` (uid 1000), no root, no sudo.
- **`config.toml` is already the SSoT for bot enumeration** — `[[auth.telegram_bots]]` and `[[auth.discord_bots]]` arrays are loaded by adapter bootstrap. Reuse this list; do not introduce a second source.
- **Idempotent `make quadlet-install`** — re-running must not produce different output, and `git pull` followed by `make quadlet-install` must always converge to a working Quadlet.
- **Webhook secret variant** — the template comment already references `lyra-bot-<platform>-<bot_id>-webhook` → `bot_webhook-<bot_id>`. The render must support this future variant without rework.
- **Multi-host** — solution must work for any host (M₂ image-worker, future hosts) that runs adapters; each host renders for its own bot subset.

## Out of Scope

- **Deeper inversion of secret-mount indirection** (apps reading `/run/secrets/bots/telegram/*` directory secret instead of N file secrets) — deferred to a separate ADR. This frame ships the minimal-diff template-render fix.
- **Migration of `lyra-nats-*` seed secrets to the same render pipeline** — those use the `Secret=lyra-nats-<role>,target=lyra-nats-<role>.seed` shape, are already 1:1 with the Quadlet (no per-bot fan-out), and are not affected by the cascade. Out of scope here.
- **CI integration tests that boot a container with the rendered Quadlet** — covered by #1361 item 5 (separate follow-up). This frame ships only the static CI guard (grep-based) for tracked-template purity.
- **Refactoring the install.sh deploy flow** beyond inserting the render step — `git pull` + `quadlet-install` ordering stays the same.

## Premise Validity

**Success in 6 months:** Zero splice-wipe recurrences. `git pull origin staging` on M₁ followed by `make quadlet-install` produces correct per-bot Quadlet directives without operator intervention. New bot onboarding works end-to-end without editing any tracked file.

**Failure in 6 months:** (a) Another adapter crash-loop traced to missing `Secret=lyra-bot-*` mounts occurs within 6 months, **OR** (b) `grep -rE '^# --- BEGIN .* ---' deploy/quadlet/` finds a new manual-splice block (the pattern reappears elsewhere in deploy/).

**Simplest alternative:** Commit the per-host `Secret=lyra-bot-*` lines directly to `deploy/quadlet/lyra-{telegram,discord}.container` and let each host pull its own branch.

**Why not simplest:** Defeats the deploy-from-staging model — each host diverges from `staging`, future PR merges produce conflicts, and the cascade class (operator-local mutations to tracked files) isn't eliminated, just relocated to per-host branches that drift independently.
