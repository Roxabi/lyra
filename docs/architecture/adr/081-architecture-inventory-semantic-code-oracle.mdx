---
title: "ADR-081: Architecture inventory via a semantic CodeInventory oracle (not per-gate textual heuristics)"
description: Replaces the textual resolver in the ADR-080 doc-drift gate with a small in-tree semantic oracle that answers identifier existence exactly and deterministically from authoritative sources.
---

## Status

Accepted (2026-05-30). Refines ADR-080.

## Context

ADR-080 (2026-05-30) established the two-tier architecture-knowledge SSoT and mandated a doc-drift CI gate (#1531, PR #1535) to make silent inventory rot loud. That decision remains valid. This ADR fixes **how the gate resolves identifiers** — the mechanism ADR-080 left implicit.

The PR #1535 implementation used a **textual resolver**: it guessed a token's semantic kind from regex shape, then approximated existence with `grep` substring matching and manual path construction. A root-cause pass on 2026-05-30 identified one underlying defect with several verified symptoms:

- `module.ClassName` was mis-resolved as a module path → 6 live classes (`OutboundEmitter`, `LlmClient`, and others) were wrongly baselined as dead.
- Substring `grep` with no word boundary → a deleted symbol "resolved" via a longer name that happened to contain it (`WorkerPool` passing because `WorkerPoolClient` exists) — a structural false negative.
- NATS subjects (`lyra.clipool.cmd`) were misclassified as dead Python modules — the resolver had no subject source.
- Single-word class names (`Hub`) were silently skipped by an `upper >= 2` heuristic; `_SKIP_SYMBOLS` was hand-maintained, inverting the "code is the SSoT" axiom.
- Approximately 25 of 121 baseline entries were resolver artefacts, not genuine doc-rot — corrupting the #1536 burn-down and violating the "falsification step" principle identified in prior feedback.

The irony is direct: the gate built to fight inventory-rot itself relied on a non-authoritative, approximate inventory oracle — exactly what ADR-080's retrieval ladder forbids ("code = inventory SSoT; derive, don't approximate").

A reuse investigation evaluated three existing tools: **cocoindex / `ccc`** (semantic vector search, fuzzy/ranked, torch + daemon), **GitNexus** (Node.js graph DB, ranked candidates, minutes-long cold index), **code-graph-ai** (Rust tree-sitter, symbol/path only, subprocess). All three are AI-exploration tools answering "what is similar/related" (ranked, out-of-process); none answers "does X exist" (exact, deterministic, in-process), and none reads `acl-matrix.json` — so none can cover the `subject` kind. `pyright` and stdlib `ast` were available but unused.

## Options Considered

### Option A: Patch the textual resolver symptom-by-symptom
- **Pros:** smallest diff; no new file.
- **Cons:** stays heuristic by design — each fix addresses one symptom while leaving the approximate foundation intact. Issues #1532 and #1533 would each re-hand-roll a resolver, producing parallel-path drift with no shared authority.

### Option B: Reuse an external tool (ccc / GitNexus / code-graph-ai)
- **Pros:** no new in-tree code.
- **Cons:** wrong tool class — ranked retrieval ≠ exact existence check. All three are out-of-process and require cold-start index builds; none has NATS-subject awareness. Integration overhead exceeds building, and coverage would be lower. The retrieval ladder reserves these tools for the semantic rung, not the exact rung.

### Option C: Build a small in-tree semantic oracle (chosen)
- **Pros:** exact and deterministic; covers all four kinds (module, symbol, subject, path) from authoritative sources; built once, shared across the gate (#1531), the Tier-1 snapshot (#1532), and the subject-literals check (#1533). No external dependencies or cold starts.
- **Cons:** ~200 lines to write and maintain; `ast` sees only static definitions (dynamically-created symbols are rare; `grep` shared the same blind spot). Syntax errors in individual files must be handled gracefully (exit 2).

## Decision

Adopt **Option C**: build `tools/code_inventory.py`, a small in-tree semantic oracle that answers `resolve(token) → {exists: bool, kind: module | symbol | subject | path | unknown}` exactly and deterministically.

The oracle's authoritative sources map directly to the identifier kinds it resolves:

| Kind | Source |
|---|---|
| `module` | stdlib `ast` walk of `src/` — module paths and their `import`/`from` statements |
| `symbol` | stdlib `ast` — class, function, and constant definitions within resolved modules |
| `subject` | `deploy/nats/acl-matrix.json` + `roxabi-contracts` `SUBJECTS` constants |
| `path` | filesystem existence check |

This makes the oracle the operational definition of ADR-080's "Tier-1 generated current-state": it derives identity from the same sources that define the code, never from textual approximation.

**Gates assert against the oracle; they never re-derive identity textually.** The baseline is regenerated by the oracle and must be falsified — every entry is confirmed dead before it is baselined, eliminating the class of artefact entries that corrupted #1536.

## Consequences

### Positive
- The false-positive and false-negative classes are eliminated by construction: `module.ClassName` resolution, substring collisions, subject misclassification, single-word skipping, and `_SKIP_SYMBOLS` all disappear.
- One shared oracle feeds the doc-drift gate (#1531), the Tier-1 snapshot (#1532), and the subject-literals check (#1533) — no parallel resolvers, no drift between gates.
- The #1536 burn-down becomes trustworthy: baseline entries are genuine doc-rot, not resolver noise.
- The retrieval ladder from ADR-080 is honored: the exact rung (code + generated) is served by the oracle; `ccc` remains the semantic/fuzzy rung; GitNexus and code-graph-ai remain optional off-CI exploration tools.

### Negative
- Approximately 200 lines to maintain in `tools/code_inventory.py` (partially offset by deleting `_classify_token`, three `_resolve_*` functions, and `_SKIP_SYMBOLS` from the gate).
- `ast`-based resolution sees only statically-defined symbols; dynamically-created ones are invisible — same limitation `grep` had, but now explicit and documented.
- The oracle must handle per-file syntax errors without aborting (exit 2 protocol required).

### Neutral
- Issues #1532 (Tier-1 snapshot = oracle serialized to JSON) and #1533 (subject-literals check = oracle's subject set) are re-scoped around the shared module; their implementation surfaces change, their goals do not.
- ADR-080 remains fully valid — this ADR refines its Tier-1 implementation, not its two-tier model or retrieval ladder.
