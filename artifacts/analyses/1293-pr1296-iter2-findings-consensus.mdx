### Rationale (debate notes)

**F1 — 2-1 reconciled via hybrid.** Architect + devops preferred Solution 2
(`test -f` post-genkeys, semantically correct: assert the output exists
before the secret-install consumes it). Security preferred Solution 1
(`test -d` pre-genkeys) plus a bonus post-write `test -s` to catch
corrupt/empty writes. The hybrid (`test -s` post-genkeys) is strictly
stronger than `test -f` (also catches empty files) AND addresses security's
corrupt-write framing AND satisfies the "guard immediately before consumer"
semantic from architect/devops. Pre-genkeys `test -d` is dropped: if the
directory is missing, `lyra-acl genkeys --regen-authconf` exits non-zero on
its own and `make` propagates the failure — `test -d` adds no information.

**F3 — 2-1 majority.** Architect + devops chose `$(DEPLOY_HOST)` (canonical
SSoT used everywhere else in the Makefile). Security raised the
"undefined-variable landmine" concern via a literal hostname or `?=`
default. The landmine is fully addressed by using a *defined* variable;
`$(DEPLOY_HOST)` is defined in `.env`. Literal hostname is rejected because
it diverges from existing Makefile convention and adds maintenance cost.

### Trade-offs

- F1 hybrid creates an implicit contract: `lyra-acl genkeys --regen-authconf`
  MUST write a non-empty `auth.conf` to `$(LYRA_NKEYS_DIR)` or the recipe
  aborts before the destructive `podman secret create --replace`. This is
  the desired fail-safe property.
- F2 is purely additive doc; no risk.
- F3 is in a *proposed* snippet (not yet in Makefile); zero runtime risk
  even if wrong, but the rename closes a copy-paste landmine.

## Alternatives

| ω | Proposed by | Rejected because |
|---|-------------|------------------|
| F1 Solution 1 alone (`test -d` pre-genkeys) | security | Catches misconfiguration but not corrupt writes; weaker than hybrid. |
| F1 maximalist (both `test -d` pre + `test -s` post) | security | Belt-and-suspenders; `test -d` adds no signal since `lyra-acl` would fail first. |
| F1 Solution 2 with `test -f` instead of `test -s` | architect/devops | `test -s` is strictly stronger (catches zero-byte file) at same cost. |
| F3 literal hostname `roxabituwer` | security | Divergent from `$(DEPLOY_HOST)` convention used by all other remote recipes. |
| F3 `PROD ?= roxabituwer` default | security | Introduces a second variable for the same concept; noise vs. SSoT. |
| F4 inline "(historical)" annotation | (panel canvassed) | ADR `status:` frontmatter + redirect banner already convey this. Editing one-time migration records sets a bad precedent. |

## Dissent

- **F1 — security:** would have preferred a pre-genkeys `test -d` as primary
  guard (fail-fast on misconfiguration); accepted the hybrid because
  post-genkeys `test -s` covers the same misconfiguration case (via lyra-acl
  failure → make abort) plus the corrupt-write case.
- **F3 — security:** would have preferred a literal hostname; accepted
  `$(DEPLOY_HOST)` once aligned with the defined-variable invariant.

Both dissents accepted via reconciliation; recorded for traceability.
