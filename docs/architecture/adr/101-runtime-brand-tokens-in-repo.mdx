> **Current truth** → [`brand/`](../../../brand/) + [`packages/shared/src/brand.ts`](../../../packages/shared/src/brand.ts){#current-truth}
> This ADR is preserved as a decision record. For up-to-date token values and structure, read the `brand/` directory itself.

## Status

Accepted — 2026-07-02. Supersedes ADR-042's "no `brand/` directory in any project repo" invariant, recording the 2026-07-01 operator decision (see ADR-042's Amendment). The exploration-brand → forge half of ADR-042 still stands.

## Context

ADR-042 (2026-03) solved a real problem of its time: AI-exploration brand assets (brand books, avatar PNGs, generation prompts and scripts, galleries, `forge.yml`) were polluting project repos — binary noise in diffs, dirty trees during brand sessions, split-brain authority between repo and forge. The eviction to `~/.roxabi/forge/{project}/brand/` was executed and holds to this day.

What ADR-042 never contemplated is **runtime design tokens**. It predates the shadcn → Astryx dashboard migration (epic #2087), which made brand values a build/runtime dependency of the product itself:

- `apps/dashboard/src/index.css` imports `brand/core.css` *(2026-07-04: corrected — actual imports are brand/core.css (line 24) and brand/reset.css (line 11), not brand/styles.css — see apps/dashboard/src/index.css)* into a dedicated `brand` CSS layer (`@layer reset, theme, base, astryx-base, astryx-theme, brand, components, utilities`).
- `apps/dashboard/src/astryx-theme/roxabi.theme.ts` maps `brand/tokens/*.css` custom properties onto Astryx token names via `var(...)` — no values duplicated, single authority in CSS.
- The dashboard's inline theme bootstrap (`apps/dashboard/index.html`) relies on `brand/tokens/colors.css` following the light/dark toggle.

A design-system SSoT that the application imports at build time cannot live in a Google-Drive-synced directory outside git: it must version, review, and deploy with the code that consumes it.

## Decision

The boundary between the two brand categories is:

| Category | Contents | Canonical location |
|----------|----------|--------------------|
| **Exploration brand** | Brand books, avatars, generation prompts/scripts, galleries, `forge.yml`, concepts | `~/.roxabi/forge/{project}/brand/` — unchanged from ADR-042 |
| **Runtime brand** | Design tokens CSS (`brand/tokens/{colors,typography,spacing,motion,elevation,fonts,status}.css`), `brand/core.css`, `brand/reset.css` *(2026-07-04: corrected — actual imports are brand/core.css + brand/reset.css, not brand/styles.css)*, runtime SVG marks (`brand/assets/factory-mark-{light,dark}.svg`, `factory-favicon.svg`) | git-tracked `brand/` in-repo |

The in-repo `brand/` directory is the **design-system SSoT** consumed by the dashboard's Astryx theme. Values are authored once, in CSS.

`packages/shared/src/brand.ts` is an **explicit derived mirror** of `brand/tokens/*.css` for TypeScript consumers — its header declares "SSOT for values is CSS" and it must be updated when tokens change. It is a mirror by policy, not a second authority.

## Consequences

### Positive

- Brand tokens are versioned with the code that consumes them — no fresh-clone bootstrap gap, no out-of-band sync required for the dashboard to build.
- Theme changes are reviewable in PRs: a token diff and its UI consequences land in the same reviewable change, gated by CI (`theme_build_drift`, dashboard build/test gates).
- The runtime never reads from `~/.roxabi/forge/` — that invariant from ADR-042 is preserved, now by construction.

### Negative / follow-up

- Other Roxabi repos with runtime brand needs must align with this boundary, and `~/projects/docs/brand-canon.md` must be updated to record it — both out of factory scope (cross-repo follow-up noted in ADR-042's Amendment).
- The `brand.ts` mirror can drift from the CSS tokens; the mirror-by-policy discipline (update on token change) is manual.

## Supersession note

ADR-042 is amended and archived as a historical record. Its forge half remains true: exploration brand assets live in `~/.roxabi/forge/{project}/brand/`, synced via Google Drive, and never re-enter the repo. Only its absolute "no `brand/` in any repo" invariant is superseded by this record.
