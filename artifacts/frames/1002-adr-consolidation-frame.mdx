## Problem Statement

We have 37 live ADRs (Architecture Decision Records) + 27 archived. Many are granular fixes that should be consolidated:

- **NATS (11 ADRs):** Incremental extraction created 11 separate ADRs for NATS-related decisions
- **Deployment (7 ADRs):** Quadlet migration generated multiple incident-driven ADRs
- **Architecture (4 ADRs):** Hexagonal/layer decisions spread across multiple documents

This creates:
- Navigation friction (readers must piece together related decisions)
- Maintenance burden (cross-references drift)
- Cognitive overhead (too many files to track)

## Constraints

1. **No information loss** — all decisions must be preserved in merged documents
2. **Archive with forward pointers** — merged ADRs go to `archive/` with "Superseded by ADR-XXX" note
3. **Update cross-references** — find/replace links in other docs
4. **Preserve ADR numbering** — merged ADRs retain their numbers in archive

## Success Criteria

- ADR count reduced from 37 to ~20-25
- Each domain has 1-2 cohesive ADRs (not 5-11 scattered ones)
- All merged ADRs archived with forward pointers
- No broken links in documentation
- `make linkcheck` passes (if available)
