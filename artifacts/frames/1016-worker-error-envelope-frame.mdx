## Problem

Every NATS worker boundary silently drops error context. When a worker (clipool today; llm-worker, voice/image, future harness) fails, the hub receives an `is_error` flag with no message and the user sees a bare `❌` or the generic fallback _"Something went wrong. Please try again."_

The original issue scoped this as a small additive fix on `CliChunkEvent`. After auditing the full NATS surface (contracts + SDK + workers + drivers + hub + adapters), the gap is **cross-cutting** rather than domain-local:

- **5 reply envelopes**, **4 different error contracts**, **0 consistent field name** for the human-readable message.
- **3 SDK silent-drop sites** in `roxabi-nats` (driver-stream timeout, adapter-receive parse failure, circuit-breaker poll-only).
- **0 structured error telemetry** end-to-end — bare ❌ is the only signal in production today, so regressions are unobservable.
- **1 hardcoded English fallback** in `stream_processor`, with no `code`-based dispatch and no path to i18n.
- **2 divergent error shapes inside the same driver** (`NatsLlmDriver.complete()` returns `LlmResult(error=…, retryable=…)`; `NatsLlmDriver.stream()` yields `ResultLlmEvent(is_error=True, error_text=…)`) — different timeout strings, different field names, same conceptual failure.

A safety-net fix already landed in `603c9472` (stream_processor + nats_driver). The contract gap remains: there is no canonical, structured, cross-domain error payload that workers populate, the SDK can synthesize for transport failures, and the hub consumes uniformly.

This frame supersedes the original F-lite framing on the issue. The bump is justified by the SDK-side silent-drop sites: patching only `CliChunkEvent` leaves transport-layer failures unobservable for every other domain, and adopting a unified envelope per-domain later costs strictly more than once.

## Who

- **Primary:** End users on Telegram/Discord — meaningless ❌ or generic "try again" today instead of actionable errors.
- **Secondary:**
  - **Hub developers** — need `retryable` to drive circuit-breaker / retry-prompt logic instead of pattern-matching free-text.
  - **Future worker authors** (harness #988, llm-worker, future agentic workers) — need a contract to populate from day one rather than reinventing the field per domain.
  - **Operators / on-call / log readers** — need structured `code` + `detail` for machine-grouping, alerting, and adoption telemetry rather than ad-hoc string matching.
  - **Adapter authors** — need stable `code` lookup as the foundation for future i18n (P6 / separate epic).

## Constraints

### Contract & rollout

- **Additive-only** per ADR-049 (`extra="ignore"` forward-compat). `CONTRACT_VERSION` stays at `"1"`. Every change in this issue is a new optional field; nothing removed.
- **Generation marker** for observability — log `roxabi_contracts.__version__` at process startup. Dashboards key off package semver, not `contract_version`.
- **Cross-repo skew tolerated** during rollout — voiceCLI / imageCLI pin contracts by tag in their own `pyproject.toml`. Field absence on old replies is non-failure (`extra="ignore"`).
- **No removal in this issue.** Phase 5 (deprecate `is_error` / `ok`) struck — `@model_validator` invariants on Tts/Stt/Image/LlmResponse are gated on `ok`; removing it would force coordinated cross-repo deploys for near-zero value.

### Design

- **`WorkerError` lives on reply envelopes only** — the 5 reply contracts (`CliChunkEvent`, `LlmChunkEvent`, `LlmResponse`, `TtsResponse`/`SttResponse`, `ImageResponse`). **Excluded**: `CliControlAck` (no error path uses it; speculative addition forbidden).
- **Open string codes**, not Pydantic Literal — Literal would force a contract version bump on every new code, contradicting ADR-049's additive-only minor-bump rule. Validity enforced by a registry shipped in P1 (Python module + Markdown table).
- **`ok` and `is_error` flags remain.** Their `@model_validator` invariants are load-bearing on non-streaming responses. `worker_error` is additive alongside, not a replacement.
- **SDK synthesis is driver-side only.** `_stream_gen` (timeout, JSON parse) can synthesize `WorkerError(code="transport.*")` because the inbox reply subject is known. `_dispatch` (worker-receive direction) has no reply subject available — documented as P3 scope constraint, not solved here.
- **Hub side single helper** — `_extract_worker_error(reply) -> WorkerError | None` is the one place hub reads error context. Replaces the hardcoded English fallback.

### Process

- **ADR required before code.** Touches ≥2 packages (`roxabi-contracts`, `roxabi-nats`), introduces a new cross-cutting pattern. Supersedes the worker→hub portion of ADR-006 (which decided "always send error response" for hub→adapter only). Normative on the code registry.
- **Adoption telemetry is part of P1, not optional.** P2's "delete the short-term `error_text` shim" gate is unenforceable without it. P1 ships `worker_error_received_total{code, domain}` and `worker_error_populated_total{domain}` counters.
- **Phase 2 shim deletion is metric-gated** — populated counter non-zero AND legacy `error_text` counter = 0 for 48h in prod before removal.

### Coordination

- **Coordinate with #839** (port llm domain to contracts) — field additions on `LlmChunkEvent` / `LlmResponse` plan together to avoid double migration.
- **Coordinate with #734** (roxabi-nats SDK v0.2.0) — contract versioning ride-along.
- **Quadlet migration is independent** — `extra="ignore"` handles independent container restarts; proceed regardless of supervisord/Quadlet state.
- **Known coupling for P3** — `NatsLlmDriver` predates `NatsDriverBase` (duplicate heartbeat / `_any_worker_alive` logic). Flag for whoever picks up P3.

## Out of Scope

- **OTel (#667)** — `WorkerError` is the transport contract; OTel is the observability layer that wraps it. Counter-shipping in P1 is a tactical adoption-gate metric, not a full instrumentation story.
- **i18n of user-facing messages (P6 / separate epic)** — hub maps `code` → locale string later. `WorkerError.message` remains the fallback.
- **Retry orchestration at the hub** — circuit-breaker policy, backoff schedules, retry-prompt UX. `retryable` is exposed; the consumer is a separate concern.
- **`_dispatch` synthesis** (worker-receive direction) — no reply subject available. Not solvable inside `roxabi-nats` without a contract change to the request envelope. Out of scope for this issue series.
- **Phase 5: deprecating `is_error` / `ok`** — struck per architect review. Invariants are load-bearing; churn cost > value.
- **`CliControlAck`** — speculative addition; no error path uses it.
- **Migrating non-NATS error paths** (HTTP boundaries, internal hub exceptions, adapter-internal errors) — this issue covers worker→hub NATS replies only.

## Complexity

**Tier: F-full** (overrides issue body label which was `size:F-lite` — superseded after audit; label updated).

Signals observed:

- **3+ domains touched**: `roxabi-contracts` (5 schemas + new model + registry), `roxabi-nats` (driver-side synthesis in P3, but design must accommodate from P1), `lyra` (clipool worker, llm driver, hub extractor, stream processor, adapters' rendering).
- **2 packages** (`roxabi-contracts`, `roxabi-nats`) + main repo (`lyra`).
- **New cross-cutting pattern** (`WorkerError` envelope + hierarchical code namespace + open-string-with-registry validation) introduced as the canonical shape for all NATS reply errors.
- **ADR threshold met** — 2+ packages + new pattern + supersedes prior decision (ADR-006 worker→hub gap).
- **Cross-repo coordination** required for P4 (voiceCLI, imageCLI) and any future removal phases.
- **Phasing across multiple issues** — #1016 owns design + P1 + P2; P3 and P4 spawn child issues; P6 is a separate epic.
- **Adoption-gate telemetry** as part of contract delivery — not a typical "patch a Pydantic field" change.

Original `size:F-lite` label reflected the surface fix on `CliChunkEvent` only. Once the SDK silent-drop sites and the cross-domain inconsistency are in scope, the architectural impact crosses from "single domain, clear scope" into "cross-cutting, new pattern, ADR-required" territory.
