## Context

Derived from [frame](../frames/984-thread-store-teardown-bootstrap-frame.mdx).

`ThreadStoreProtocol.close()` exposes store ownership to adapters. Both the standalone path (`adapter_standalone.py`) and the unified path (`bootstrap_lifecycle.py` via `wire_discord_adapters`) currently rely on `DiscordAdapter.close()` to close `dc_thread_store` — an implicit contract that is fragile and inconsistent with the error path (which closes it explicitly in `bootstrap_wiring.py:222-224`).

The unified path compounds the problem: `wire_discord_adapters` creates `ThreadStore` internally but does not return it. After adapters close, `run_lifecycle` has no reference to close it — it relies entirely on `DiscordAdapter.close()`. Removing `close()` from the adapter without surfacing the store through `wire_discord_adapters` → `_wire_adapters` → `run_lifecycle` would leak the store in unified mode.

No `isinstance(x, ThreadStoreProtocol)` checks exist that would break when `close()` is removed.

Note: `thread_store_protocol.py` was recently updated to add a `ThreadSession` dataclass and change `get_session` return type — this issue only removes `close()`, no other protocol changes.

## Goal

Remove `close()` from `ThreadStoreProtocol` and ensure `dc_thread_store` is closed explicitly by bootstrap — in both standalone (`adapter_standalone.py`) and unified (`bootstrap_lifecycle.py`) paths — after adapter teardown completes.

## Users

- **Bootstrap layer:** resource lifecycle is fully owned and explicit in both process modes
- **Future adapter implementors:** `ThreadStoreProtocol` is a clean reader/writer API with no ownership semantics

## Expected Behavior

After the change:

1. `ThreadStoreProtocol` declares only read/write methods (`get_thread_ids`, `is_owned`, `get_session`, `claim`, `update_session`). No `close()`.
2. `DiscordAdapter.close()` no longer calls `self._thread_store.close()`. The `if self._thread_store is not None` block that calls `close()` is removed.
3. `wire_discord_adapters` returns a 3-tuple: `(adapters, dispatchers, thread_store | None)` instead of the current 2-tuple.
4. `_wire_adapters` in `wiring_helpers.py` captures the returned `thread_store` and returns a 5-tuple: `(tg_adapters, tg_dispatchers, dc_adapters, dc_dispatchers, dc_thread_store)`.
5. `run_lifecycle` in `bootstrap_lifecycle.py` receives `dc_thread_store` and calls `await dc_thread_store.close()` after all `dc_adapter.close()` calls complete, before NATS closes. `None`-guarded.
6. `adapter_standalone.py` — which already holds `dc_thread_store` directly — calls `await dc_thread_store.close()` in the inner `finally` block (same block as `dc_turn_store.close()`, after the `ibus.stop()` loop), before NATS closes.
7. `bootstrap_wiring.py` comment at line 133 is updated: removes "closed by the first adapter's close()" wording.

On SIGTERM in standalone, teardown order:
adapters close → `ibus.stop()` loop → `dc_thread_store.close()` → `dc_turn_store.close()` → `nc.close()`

On SIGTERM in unified, teardown order:
`dc_adapter.close()` loop → `dc_thread_store.close()` (in `run_lifecycle`) → NATS / other cleanup
