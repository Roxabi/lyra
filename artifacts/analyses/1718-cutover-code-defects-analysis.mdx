## Source

Issue #1718 (postmortem of the #1670 `factory.*` prod cutover, `artifacts/postmortems/2026-06-03-1670-prod-cutover-blockers.md`). 8 genuine code defects exposed by the cutover, rename-independent. Tracker #1710, epic #1671.

Design driven interactively (2026-06-03) with 3 expert agents (architect, devops, axial) — see `## Fit Check`.

## Problem

The deploy + seed path has three failure themes, all of which bit a live prod host during the cutover:

1. **Secret-list drift (#9, +#13)** — the per-container NATS-secret list is hand-maintained in `deploy/install.sh` `SEEDS` (line 66) and `Makefile quadlet-secrets-install` (line 208) and **drifted** (install.sh missing `factory-nats-gh-helper`). Neither derives from any SSoT. The ecosystem standard already *mandates* `deploy/quadlet.toml` `required_secrets` as the per-repo manifest (`~/projects/docs/container-deployment-standard.md` S2) — but **nothing enforced it**, and it is itself wrong on 5/8 components.
2. **Non-atomic install (#12, root-caused by #11)** — `make quadlet-install` runs `rm -f $QUADLET_DIR/factory*` (line 151) *before* a fallible `uv run factory bot init` (line 162). `bot init` fails (#11), aborting mid-sequence → units deleted-but-not-recopied → half-installed deployment that can brick a live host.
3. **Identity / data-dir split-brain (#7, #10) + symlink hazards (#13, #14)** — `factory-acl genkeys` writes seeds to `~/.lyra/nkeys` while everything else reads `~/.roxabi/factory/nkeys` (#10); its root guard mis-owns rootless seeds (#7); install.sh symlink + cross-ns bridge symlink assumptions break (#13, #14).

## Outcome

A fresh operator runs `deploy/install.sh` / `make quadlet-install` on a clean or live host → healthy deployment, zero manual fixups. Adding an ACL identity auto-propagates to the installed secret set; a drift gate makes silent drift impossible. `factory-acl` resolves one data dir, honors `ROXABI_FACTORY_DIR`, and does not need root for rootless seed generation.

## Appetite

One focused cycle. F-full (multi-domain), but each defect is a bounded fix; #9 is the only one with real design weight.

## Shapes — defect #9 (the only one needing a shape decision)

Three options were debated; **all 3 agents rejected B** (target-axis-trap), and the final model aligns to the *existing ecosystem standard* (S2) rather than a factory-local invention.

### Shape A — new `deploy/containers/<name>.toml` descriptor (1 file/container)
SSoT for the deploy facet; remove `deploy` block from acl-matrix. **Rejected:** duplicates `quadlet.toml`, which already models this; off-standard; more churn.

### Shape B — descriptor = total SSoT, acl-matrix generated
**Rejected unanimously:** axial `target-axis-trap` — puts NATS subjects (transport axis) into per-container descriptors (deploy axis); re-roots the entire ADR-064 ACL pipeline (706 spec, v3-current fixture, auth.conf, CURRENT.generated.md). Max blast radius.

### Shape C — `quadlet.toml` is the declared SSoT (standard-aligned) ◀ chosen
`deploy/quadlet.toml` `required_secrets` is **already** the per-repo manifest the ecosystem standard mandates (S2) and the sketched central `~/projects/deploy.sh` consumes. Make it authoritative:

```
DECLARED SSoT (S2 standard — edited by humans, read by cross-repo deploy.sh):
    deploy/quadlet.toml  required_secrets   per [component.<name>]
        │  install.sh + Makefile derive from it (python tomllib read → committed
        │  deploy/generated/secrets-manifest.sh, sourced by install.sh — zero
        │  runtime python dep on M₁)
        ▼
GATE (enforcement — factory = reference impl, tools/check_*.sh, pre-push + CI on deploy/):
    required_secrets  ==  Secret= directives in deploy/quadlet/*.container(.tmpl)
                          (runtime-enforced ground truth; filter owner=factory)
                      ==  acl-matrix identities where deploy.type==container
                          AND owner=="factory"  (NATS axis cross-check)
    secret in a unit with no required_secrets entry  →  HARD FAIL
    optional secrets (gh-pem, claude-oauth)          →  SKIP log, ¬gate failure
```

**Why the units are the gate authority, not the SSoT:** a `Secret=` missing from a unit hard-fails container boot — runtime-self-validating. They are the perfect *validator*, but the *declared* SSoT stays `quadlet.toml` to honor S2 and feed the cross-repo `deploy.sh` + the `architecture_snapshot` gate (which already reads `required_secrets`).

## Fit Check

Chosen: **Shape C** — 3× GO from architect / devops / axial on the refined model.

- **Standard alignment** — `container-deployment-standard.md` S2 already declares `quadlet.toml` the per-repo secrets manifest. Shape C makes the existing-but-unenforced standard *true*; the units+acl-matrix cross-check is the missing enforcement that would have caught #1670. Factory is the documented **reference implementation**; voiceCLI/llmCLI/imageCLI adopt the same pattern per-repo (deploy is a **doc-standard + per-repo deliverables**, NOT a shared package — unlike `roxabi-contracts`/`roxabi-nats`).
- **Axial** — acl-matrix stays NATS-axis SSoT; `quadlet.toml`/units own the deploy axis; gate is read-only cross-check (consistency invariant, ¬second SSoT). Follow-up: annotate/remove `deploy.secret` from acl-matrix once the gate ships (closes residual dual-assertion on that field).
- **Ops** — committed generated manifest = zero runtime python dep; `make converge` + auto-update timers unaffected (Makefile migration is a follow-up pass). Gate is repo-only set-membership, never touches live Podman.

### Cross-repo boundary (scoping trap — codify in gate)

`deploy/quadlet/` in this repo holds **only `factory-*` units (7 NATS-seed identities + auth.conf)**. acl-matrix lists 14 identities across owners:

| owner / type | identities | unit lives | secret installed by |
|---|---|---|---|
| factory / container | hub, telegram-adapter, discord-adapter, clipool-worker, turn-writer, blobstore, gh-helper | **this repo** | this repo |
| voicecli / container | voice-tts, voice-stt | voiceCLI repo (runs on M₁) | voiceCLI |
| external | llm-worker, llm-operator, image-worker, voice-client | llmCLI/imageCLI (M₂) | those repos |
| host | dashboard-reader | seed file, ¬podman secret | — |

acl-matrix lists voice/external identities only because it renders the **merged `auth.conf`** (the M₁ NATS server must authorize all connecting identities). The gate cross-check **MUST filter `owner=="factory"`** or it false-positives on `voicecli-nats-*`.
