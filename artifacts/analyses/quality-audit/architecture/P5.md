### Recommendations (prioritized, with effort estimate)

1. **Extract `MAX_DELIVER` to contracts layer** (P2, effort: S) — Move `lyra.infrastructure.outbound_audio.stream_setup.MAX_DELIVER` to `roxabi_contracts` or `lyra.core.messaging` so `JetStreamAudioConsumer` stops importing infrastructure. This fixes the only adapter→infrastructure layer violation in the partition.

2. **Unify platform CLI commands** (P2, effort: S) — Replace `telegram.py` and `discord.py` with a single parameterized generator that registers commands per platform. This eliminates the N×M duplication and removes the risk of the two files diverging on flag changes. The `_commands.py` shared layer already exists; the platform files are just thin wrappers that can be generated.

3. **Break `discord_audio` → `discord_inbound` circular dependency** (P2, effort: M) — The local import at line 255 of `discord_audio.py` is a smell. The shared `build_discord_inbound_ctx` and pipeline-running logic should be extracted to a `lyra.adapters.discord._pipeline_runner` module or promoted to the shared layer so both `discord_audio` and `discord_inbound` can import it without cycling.

4. **Relocate `push_to_hub_guarded` and shared types to `lyra.core`** (P2, effort: M) — The `inbound` → `adapters.shared` coupling is gated as debt (#1287). `PushGuardDeps`, `TypingTaskManager`, and `OutboundListener` should move to `lyra.core.messaging` or a new `lyra.shared` package so inbound stages no longer depend on adapter internals. This is the root cause of the bidirectional coupling.

5. **Extract inbound pipeline bootstrap helper** (P2, effort: S) — Both `telegram_inbound.py` and `discord_inbound.py` duplicate the same module-level `_dispatcher`, `_router`, `_session_builder`, `_pipeline`, `_parser_cache` pattern. A single `make_pipeline(parser_cls)` factory in `lyra.adapters.shared` would collapse ~40 lines of duplication per platform.

6. **Remove `DiscordFormatter` → `discord_outbound` fallback call** (P2, effort: XS) — `DiscordFormatter.send_fallback` should delegate to the adapter's `send()` method directly (already available via `self._adapter`), rather than importing the standalone `send` function from `discord_outbound`. This breaks the formatter→outbound cross-module coupling.

7. **Evaluate `PendingAttachment` location** (P3, effort: S) — `PendingAttachment` is imported by adapters from `lyra.inbound.attachment_ingest`. Since it is consumed by both adapters and inbound stages, consider promoting it to `lyra.core.messaging` to make the dependency direction unambiguous.

8. **Audit `clipool_worker` abstraction** (P3, effort: M) — The clipool worker is tightly coupled to `lyra.core.cli.cli_pool` and `lyra.core.agent.agent_config`. Consider whether a port/protocol boundary (similar to `BlobStorePort`) would reduce coupling between the NATS worker and core CLI pool internals.
