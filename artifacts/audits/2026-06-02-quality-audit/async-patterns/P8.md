# Async Patterns Audit — Partition P8 (LLM, agents, stages, misc)

## Summary

Two P2 issues confirmed: synchronous `open()` calls inside `check_nats_varz` (async) block the event loop for state file I/O. Five P3 issues found: sync file I/O / CPU-bound crypto / blocking system calls inside async functions that should be offloaded to threads. No P0 or P1 issues (race conditions, unawaited coroutines, task leaks, event loop misuse) were found.

## Verified Clean Patterns

- `subprocess.run` in `checks_log.py` / `checks.py` — properly offloaded via `asyncio.to_thread` in `run_checks`
- `asyncio.create_subprocess_exec` in `integrations/`, `escalation.py`, `cli_pool_spawn.py` — all properly awaited with `asyncio.wait_for`
- `asyncio.create_task` in `daemon.py`, `pool.py`, `cli_pool_spawn.py`, `typing/listener.py`, `worker_pool_client.py` — all properly referenced, cleaned up, and not fire-and-forget leaks
- `asyncio.start_unix_server` in `dispenser.py` — correctly used with async handler
- `async for` over streaming iterators — correctly used in `llm_client.py`, `cli.py`, `stream_processor.py`, `outbound/emitter.py`
- `await` in all async functions — no unawaited coroutines detected
- `aclose()` on async generators — properly called in `stream_processor.py` and `_emitter_run.py`
