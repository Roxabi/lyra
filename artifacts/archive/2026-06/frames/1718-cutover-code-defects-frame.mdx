## Problem

The #1670 `factory.*` production cutover (postmortem `artifacts/postmortems/2026-06-03-1670-prod-cutover-blockers.md`) exposed eight **rename-independent code defects** in the deploy + seed path. They are not artifacts of the `lyra→factory` migration — any future operator running `deploy/install.sh` or `make quadlet-install` on a clean host will hit them. They cluster around three failure themes:

1. **Drift between seed-list SSoTs** — `install.sh` `SEEDS=(…)` (7 secrets, no gh-helper) ≠ `Makefile` `nats-secrets-install` (8, incl. `factory-nats-gh-helper`); neither is derived from `deploy/nats/acl-matrix.json`, the declared SSoT. Adding identity #1082 updated matrix + Makefile but silently not `install.sh`.
2. **Non-atomic / fallible install** — `make quadlet-install` `rm -f`s units *first*, then runs a fallible `factory bot init`; any failure leaves a half-installed deployment that can brick a live host. The triggering failure (#11) is `_BotSeedEntry` breaking-validating an existing `config.toml` (`owner_users` ints vs `list[str]` + `extra="forbid"`).
3. **Identity / data-dir resolution split-brain** — `factory-acl genkeys` root-guard mis-owns rootless seeds (#7); a second divergent nkeys dir resolution (`~/.lyra/nkeys` vs `factory_data_dir()`) ignores `ROXABI_FACTORY_DIR` (#10, untraced); plus install-time symlink hazards (#13 blob symlink over existing dir, #14 cross-ns bridge symlink must be relative).

Observable impact: the cutover required manual seed-list edits, manual symlink fixups, and a near-brick of a live host on a transient bot-init failure.

## Who

- **Primary:** future operators redeploying/cutting over `factory.*` on a clean or live host (M₁ `factory-hub` role) — they hit drift, half-installs, and mis-owned seeds.
- **Secondary:** maintainers who add an ACL identity (must currently remember to hand-edit two non-derived lists); the deploy standard owners (cross-ns symlink rule needs codifying).

## Constraints

- Rootless model: `systemd --user`, seeds owned `mickael:mickael 0600` — fixes must not require root or re-introduce root-owned seeds.
- `acl-matrix.json` is the declared SSoT — derivations must read from it, not duplicate it.
- Runtime is unaffected (hub reads `config.db`, not `config.toml`) — the seed path is what breaks; fixes must not regress the runtime read path.
- Cross-namespace (host ↔ bind-mounted container) symlinks must resolve in both namespaces.
- `#10` nkeys split-brain is **NOT fully traced** — analyze phase must trace the `genkeys` seeds-dir resolution before fixing.

## Out of Scope

- The `lyra→factory` infra rename itself (Phase 2, tracked separately) — these defects are rename-independent.
- New deploy features or topology changes — this is hardening of the existing path.
- Re-architecting the seed/secret model — fixes are minimal, targeted, SSoT-aligned.

## Premise Validity

**Success in 6 months:** All 8 defects fixed; a fresh operator runs `deploy/install.sh` / `make quadlet-install` on a clean host → healthy deployment with zero manual fixups. Adding an ACL identity auto-propagates to `install.sh` SEEDS, and a drift gate asserting `install.sh secrets == acl-matrix identities` stays green.

**Failure in 6 months:** (falsifiable) A redeploy STILL requires manual seed-list edits, OR `make quadlet-install` still leaves a half-installed deployment on a transient bot-init failure, OR the `install.sh`↔`acl-matrix.json` drift gate is absent/red after the fix lands.

**Simplest alternative:** Write a manual redeploy runbook documenting the gotchas instead of fixing the code.
**Why not simplest:** Postmortem #1670 already proved docs don't prevent recurrence — the next operator hits the same drift + non-atomic install regardless of a runbook. These are code defects (drift between SSoTs, non-atomic destructive target, breaking validation, mis-owned seeds) that require code fixes + an automated drift gate, not more prose.

## Complexity

**Tier: F-full** — multi-domain (devops deploy scripts + Makefile + ACL derivation + new drift gate; backend Python `bots/init.py` validation + `factory-acl` genkeys + nkeys dir resolution; deploy-standard docs) with a genuine unknown (#10 untraced split-brain resolution). >10 files touched.

Signals observed:
- Multiple domains: deploy/shell, build/Makefile, Python CLI, docs.
- New pattern: SSoT-derived SEEDS + drift gate (new tooling).
- Unknown: #10 `genkeys` seeds-dir resolution not yet traced; explicit env override ignored.
- 8 independent-ish defects → analysis + planning warranted to sequence + cluster.
