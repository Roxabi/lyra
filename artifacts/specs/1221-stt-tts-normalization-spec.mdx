# Spec: STT/TTS Hexagonal Normalization

> Status: complete and fixer-executable. No remaining decisions.

## 1. Goal

Eliminate `lyra.stt` and `lyra.tts` as top-level packages. Both are structural anomalies: they own no drivers, no subsystem, and no NATS plumbing — they became parking lots for errors, value objects, and pure helpers that belong either in `core/ports/` (protocol-adjacent types) or co-located with their sole consumer (`lyra.nats`). The LLM module is the reference: `core/ports/llm.py` owns the protocol + value object + error; `lyra.llm/` exists only because it owns `drivers/` + `ProviderRegistry` + decorators. After this change, `STTProtocol` / `TtsProtocol` signatures reference types defined in the same `core/ports/` file, no TYPE_CHECKING cross-package trick needed. All imports in every consumer file are rewritten to the canonical location. The NATS clients get explicit `from_wire` mapping functions.

## 2. Non-goals

- No back-compat shims, deprecation banners, or `__init__.py` re-exports. Hard delete.
- `voiceCLI`, `packages/roxabi-contracts/`, and `packages/roxabi-nats/` are not touched.
- No new ADR required: the hexagonal pattern is already established (ADR-059). This is remediation, not a new pattern.
- `AgentTTSConfig` / `AgentSTTConfig` in `core/agent/agent_config.py` are not moved — they are agent domain config, not voice domain types. They stay where they are.

## 5. Wire↔Domain Mapper Design

### Current state (inline, with asserts)

`nats_stt_client.py:transcribe()` constructs `TranscriptionResult` inline with three `assert ... is not None` guards. `nats_tts_client.py:synthesize()` constructs `SynthesisResult` inline with two assert guards.

### Decision: named mappers, no asserts

Replace inline construction with named module-level functions. Drop the `assert` guards — they strip under `python -O`, giving silent `None` propagation. Trust `_enforce_success_invariant` on `SttResponse`/`TtsResponse` instead: if that invariant is violated, the bug is there, not at the mapper. If pyright narrows `str | None` and complains, use `cast(str, resp.text)` with an inline comment referencing `_enforce_success_invariant`.

The `LlmResult.worker_error` leakage precedent (wire type in a domain type, ADR-066 P2 shim) does not apply: `SttResponse.worker_error` and `TtsResponse.worker_error` are not consumed by lyra callers. STT/TTS domain types stay pure.

### Mapper in `lyra/nats/nats_stt_client.py`

Add after imports, before `NatsSttClient`:

```python
def _stt_result_from_wire(resp: SttResponse) -> TranscriptionResult:
    """Map a validated SttResponse (ok=True, _enforce_success_invariant passed) to TranscriptionResult."""
    return TranscriptionResult(
        text=resp.text,  # type: ignore[arg-type]  # narrowed by _enforce_success_invariant
        language=resp.language,  # type: ignore[arg-type]
        duration_seconds=resp.duration_seconds,  # type: ignore[arg-type]
    )
```

Replace inline construction in `transcribe()`:
- Remove the three `assert resp.* is not None` lines.
- Replace the `result = TranscriptionResult(...)` block with `result = _stt_result_from_wire(resp)`.

### Mapper in `lyra/nats/nats_tts_client.py`

Add after imports, before `NatsTtsClient`:

```python
def _tts_result_from_wire(resp: TtsResponse, audio_bytes: bytes) -> SynthesisResult:
    """Map a validated TtsResponse (ok=True, _enforce_success_invariant passed) + decoded audio to SynthesisResult."""
    return SynthesisResult(
        audio_bytes=audio_bytes,
        mime_type=resp.mime_type,  # type: ignore[arg-type]  # narrowed by _enforce_success_invariant
        duration_ms=resp.duration_ms,  # type: ignore[arg-type]
        waveform_b64=resp.waveform_b64,
    )
```

Replace inline construction in `synthesize()`:
- Remove the three `assert resp.* is not None` lines.
- Replace the `audio_bytes = base64.b64decode(resp.audio_b64)` + `return SynthesisResult(...)` block with:
  ```python
  audio_bytes = base64.b64decode(resp.audio_b64)  # type: ignore[arg-type]
  self._cb.record_success()
  return _tts_result_from_wire(resp, audio_bytes)
  ```

**Rationale for keeping mappers in NATS client files (not `core/ports/`):** The mappers reference `SttResponse`/`TtsResponse` (wire types from `roxabi_contracts`). Placing them in `core/` would import wire types into the domain port layer. Mappers belong in `lyra.nats`, which owns the boundary.
