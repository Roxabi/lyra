### Recommendations (prioritized, with effort estimate)
1. **Extract shared adapter factories into tests/factories/adapters.py** (P1, 2-3h) — Extend existing `make_dc_adapter` / `make_tg_adapter` conftest re-exports to cover all constructor patterns (with/without `intents`, with/without `auto_thread`, with/without `watch_channels`). Replace inline constructor blocks in `test_discord_voice_commands.py`, `test_discord_watch.py`, `test_discord_threads.py`, `test_discord_snapshots.py`, `test_discord_voice_session.py`, `test_discord_voice_streaming.py`, `test_telegram_attachments.py`, `test_telegram_outbound_send.py`.
2. **Merge Discord/Telegram CLI mirror tests into a single parameterized suite** (P1, 3-4h) — Create `tests/cli/test_bot_commands.py` with `@pytest.mark.parametrize("platform", ["discord", "telegram"])` or a platform-agnostic base class. The two files are literal string substitutions; maintaining them separately risks divergence on every new CLI flag.
3. **Extract shared patch context managers in bootstrap tests** (P2, 2-3h) — `test_hub_standalone_readiness.py` has a 15-patch `with` block duplicated across two tests. Extract into a `_bootstrap_hub_patches()` context manager or pytest fixture. Same for `test_tool_display_wiring.py` (Telegram/Discord standalone mirrors) and `test_bootstrap_audio_consumer.py` (Telegram/Discord mirrors).
4. **Extract Discord message mock factories** (P2, 1-2h) — `test_discord_watch.py` and `test_discord_threads.py` both build `SimpleNamespace(...)` message mocks inline. Add a `make_discord_message(guild_id=..., channel=..., content=...)` factory to `tests/factories/adapters.py`.
5. **Break oversized test classes into smaller topical classes** (P2, 3-4h) — Split `TestHandleVoiceCommand` (280 lines) into `TestJoin`, `TestLeave`, `TestErrorPaths`. Split `TestSecretInstall` (264 lines) into `TestInstallBasic`, `TestInstallValidation`, `TestInstallWebhook`. Split `TestWatchChannels` (257 lines) into `TestWatchBasic`, `TestWatchThreadInteraction`, `TestWatchErrors`. This keeps each class under 100 lines and makes test navigation easier.
6. **Break oversized fixture `_patch_unified_boundaries` into sub-fixtures** (P2, 2h) — Split the 199-line fixture into `_patch_nats`, `_patch_stores`, `_patch_hub`, `_clipool` sub-fixtures so each test only imports the mocks it needs.
7. **Break long standalone bootstrap tests into Arrange/Act/Assert helpers** (P2, 2h) — `test_ensure_stream_and_kv_awaited_before_announce_hub_ready` (134 lines) and the Telegram/Discord audio consumer tests (109/95 lines) can extract their mock-building into `_make_nc_mock`, `_make_adapter_mock` helpers already present in the file; move the `with` patch block into a context manager.
