## §1 Intent

This playbook drives the process that bounds code-smell growth in `src/`. The direct trigger was accumulated frustration: 270+ exception markers in `src/lyra/` — `# noqa:`, `# pyright: ignore`, `# type: ignore`, `.importlinter` waivers, file/folder exemptions — all free-form prose with no way to classify, bound, or drain them systematically.

Ratchet alone is insufficient. A gate that blocks new markers still leaves the existing 270+ unaddressed, and a drain campaign without inflow control produces regrowth between passes. This pipeline layers four mechanisms in sequence: **audit** (enumerate every site), **POLICY/DEBT taxonomy** (classify intent), **ratchet** (block untagged additions and net DEBT growth), and **registry** (version-controlled debt inventory per slug). Together they bound future growth and produce a `drain-queue.json` ready for the P2a fix pass. See `artifacts/specs/1162-quality-debt-invariant-spec.mdx` for full data model and wiring.

## §2 Pre-flight

Before running this pipeline on a new repo or debt category, verify:

- `tools/audit_quality_debt.py` exists and exits non-zero on any UNTAGGED site in the target scope.
- `docs/quality-policy.md` exists with the POLICY vocabulary table (grammar, `POLICY:<tag>` definitions, DEBT lifecycle, "adding an exception" how-to, error catalog).
- `artifacts/debt/` directory exists (may be empty; `INDEX.md` is auto-generated by T1).
- Pre-commit (Lefthook) and CI (`.github/workflows/quality-debt.yml`) are wired to invoke `check_quality_debt_ratchet.sh`, but `tools/quality_debt_baseline.json` has `cutover_date` in the future — ratchet is in **soft mode** (warn-only, exit 0).
- Baseline scaffold has `generated_by: "make quality-debt-rebaseline"` and a `cutover_date` at least 7 days from the planned backfill merge.

Do NOT set `RATCHET_MODE=hard` manually before the backfill is merged. CI never sets this variable; hard mode engages automatically when `today >= cutover_date`.

## §3 Steps

1. **Land audit tool + ratchet in soft mode (CI warns, never fails).** Ratchet must be live before backfill so that any in-flight PRs surface untagged drift early without blocking them. Baseline `cutover_date = today + 7d` is committed here.

2. **Run audit → review report.** `make quality-debt-report` emits `artifacts/quality-debt-report.json` with every site bucketed as POLICY, DEBT, or UNTAGGED. Review UNTAGGED count and distribution by rule before classifying.

3. **Run classifier `--dry-run` → review TSV.** `tools/classify_quality_debt.py --dry-run` emits a proposed-tags TSV. Review the `needs_review` rows (F401 ambiguous, cross-domain PLR0913) before proceeding. Confirm ≥80% of UNTAGGED rows (excluding `needs_review`) have a deterministic POLICY suggestion.

4. **Run classifier `--apply` → inline tags + registry files.** `make quality-debt-classify` writes `POLICY:<tag>` or `DEBT:<slug>` suffixes into every site comment and creates `artifacts/debt/<slug>.md` files. No runtime code changes — comment-only edits and new files.

5. **Regenerate baseline.** `make quality-debt-rebaseline` overwrites `tools/quality_debt_baseline.json` with per-(rule, bucket, slug) counts and stamps `generated_by: "make quality-debt-rebaseline"`. Ratchet rejects baselines missing this field (forge-resistant).

   **`--reset-cutover` flag** — `rebaseline_quality_debt.py` accepts `--reset-cutover` to force the cutover date forward.

   | Scenario | Command | Effect |
   |---|---|---|
   | Routine rebaseline (default) | `make quality-debt-rebaseline` | Preserves existing `cutover_date` — no deadline drift |
   | Intentional reset after a clean slice ships | `make quality-debt-rebaseline EXTRA_ARGS=--reset-cutover` | Sets `cutover_date = today + 7d` — defers hard mode by 7 days |

   Use `--reset-cutover` only when the new backlog legitimately warrants a fresh soft window (e.g., a scope extension that adds many UNTAGGED sites). Avoid it on routine rebaselines — the default preserve behavior prevents indefinite soft-mode deferral.

6. **Set cutover date.** First rebaseline writes `cutover_date = merge-date + 7d`. Subsequent rebaselines preserve it. After that date ratchet auto-promotes to hard mode — no follow-up PR, no manual flip, no forget risk.

7. **File P2a drain epic + populate registry bodies.** One GH issue: `"Quality-debt drain pass — REFACTOR-NOW + first DEBT batch (P2a)"`, blocked-by #1162. Registry files (`artifacts/debt/<slug>.md`) already exist from step 4; populate `## Drain plan` bodies per slug.

8. **Quarterly audit of POLICY vocab.** Review `docs/quality-policy.md` POLICY table for obsolete or misused tags. Prune or deprecate. No ADR gate — direct commit sufficient.

## §5 Classification heuristics

| Rule | Default fix_class | Reasoning | Counter-example |
|---|---|---|---|
| BLE001 at CLI top-level (`cli_*.py`) | POLICY:boundary | Re-raising crashes the user-facing command; catch-all is the correct boundary | BLE001 mid-stack inside a service method → DEBT (should catch specific exception) |
| B008 with `typer.Option` / `typer.Argument` | POLICY:typer-default | Typer requires this idiom; B008 is a false positive for CLI declarations | `typer.Option` used inside a helper function called at runtime → suspicious, inspect before tagging |
| PLR0913 on wiring/bootstrap functions | POLICY:wiring | Dependency-injection ergonomic; each param is a distinct injected dep, not incidental arity | PLR0913 on a business-logic function (non-wiring) → DEBT or REFACTOR-NOW |
| C901 on `_atomic_table_copy` / migration steps | POLICY:migration-sequence | Sequential steps are irreducible; extracting sub-functions would break the atomic guarantee | C901 in normal business logic or event handling → DEBT |
| F401 in `__init__.py` re-export | POLICY:re-export OR `needs_review` | Barrel import pattern; but AST/usage check needed to confirm no other importer | F401 in non-init module where symbol is genuinely unused → remove the import |

The `needs_review` bucket is excluded from the 80% classification-rate denominator. A site in `needs_review` still gets a registry entry (`fix_class: needs_review`) — it is not abandoned, just deferred to a human-assisted P2a pass.

## §6 Anti-patterns

### Closed-issue stale comment (canonical incident)

`pyproject.toml:123` contains the comment `# ── Wave 4 (#411) — config loading migrated to Pydantic ──`, followed immediately by seven global pyright suppressions: `reportUnknownVariableType`, `reportUnknownMemberType`, `reportUnknownArgumentType`, `reportUnknownParameterType`, `reportMissingParameterType`, `reportUnknownLambdaType`, `reportMissingTypeArgument` (lines 127–133). Issue #411 is **CLOSED**. The suppressions persist. The comment claims migration is complete; the suppressions prove it is not.

Nothing in the quality gate caught this. There was no link from source to open tracking item. The fix these suppressions represent — re-enabling the rules incrementally — has no owner, no drain plan, and no machine-enforceable deadline. This is the direct motivation for the registry model: every suppression must reference either an open `POLICY:<tag>` or a `DEBT:<slug>` that maps to an `artifacts/debt/<slug>.md` file with `status: open`. When a slug is marked `drained`, any surviving reference in `src/` fails the ratchet. A closed issue with leftover suppressions cannot hide behind a stale comment.

### GitHub-issue-as-debt-tracker (rejected)

An earlier design (v2 of the spec) enforced debt by calling `gh issue view <N>` in the ratchet hot path. This recreates the same smell: when issues get closed, the source references become stale, and the ratchet either starts failing spuriously or must be bypassed. It also introduces network dependencies (`gh` API, TTL cache, auth tokens) into a pre-push hook. The file-based registry was chosen because the audit is a pure local file check — zero `gh` API calls in the ratchet hot path. Registry state is version-controlled, diffable, and reviewable in the same PR as the code change.

### Auto-fix everything big-bang (rejected)

It is tempting to run the classifier with `--apply` and immediately follow up with an automated refactor of all `easy` sites in the same PR. The RC-7 pattern from prior audits shows that a fix pass without a falsification step (behavioral equivalence check) introduces new defects. The classifier writes tags and registry files only. Runtime refactors are deferred to P2a with test coverage gating each change. The drain queue (`artifacts/quality-debt-drain-queue.json`) provides a ranked, sized inventory ready for a disciplined P2a pass — not a batch auto-apply.

## §7 Re-run recipe

To apply this pipeline to a new debt category (e.g., `tests/` in P2b, `packages/` later):

1. Extend `tools/audit_quality_debt.py` input list to include the new path glob (`tests/**/*.py` etc.).
2. Run `make quality-debt-report` → inspect UNTAGGED count and rule distribution for the new scope.
3. Extend `docs/quality-policy.md` POLICY vocabulary table if new patterns emerged that are legitimately policy-approved.
4. Run classifier `--dry-run` → review TSV → `--apply` → new `artifacts/debt/<slug>.md` registry files for new clusters.
5. Run `make quality-debt-rebaseline` → new per-(rule, bucket, slug) counts committed. `cutover_date` stays the existing value if already in hard mode; set a new one only if the new scope adds significant UNTAGGED backlog that would trigger hard failures immediately.
6. File a P2-X drain follow-up issue (blocked-by the scope-extension PR). Do not file per-instance issues — one drain epic per scope covers all slugs within it.

## §8 Generalization notes

This pipeline was built for lyra specifically (Driver C — clean lyra; phase-2 portability is contingent on phase-1 success).

**Lyra-specific:** `artifacts/debt/` registry path, `INDEX.md` format, the initial POLICY tag set, `tools/file_exemptions.txt` / `tools/folder_exemptions.txt` exemption files and their `# DEBT:<slug>` normalization.

**Liftable to dev-core (phase 2):** tag grammar definition (`POLICY:<tag>` / `DEBT:<slug>`), soft/hard cutover pattern (date-based auto-promote in ratchet), audit/ratchet split (T1 produces report; T2 consumes it — decoupled), classifier shape (rule-to-POLICY heuristics + `needs_review` bucket), registry frontmatter schema.

**Not liftable yet:** project-specific rule set (BLE001, PLR0913, C901, B008, F401, PLR0915 were selected for lyra's profile), drain epic conventions (P2a/P2b/P2-X naming), 30-item REFACTOR-NOW cap (empirical; other projects may need a different cap).

Phase-2 success metric (informational): zero new UNTAGGED sites in PRs merged during the soft window is the leading indicator that the gate is working before hard mode engages.
