## Home

This ADR lives in `lyra/docs/architecture/adr/`. Home is permanent.

Lyra is the origin of the Roxabi ecosystem — the infra (NATS server config, auth.conf, nkey issuance, Quadlet patterns, deploy scripts, CI workflow) exists because Lyra needed it. Other projects are downstream consumers. Lyra's repo is the ecosystem infra home by origin, not by convenience. `roxabi-infra` will not be created; this ADR does not move.

## Context

Let:
  M₁ := `roxabituwer` (192.168.1.16, Ubuntu 26.04 LTS, rootless Podman 5.x)
  P₁ := Phase 1 of `docs/PROD-MIGRATION-STRATEGY.md` (Lyra Quadlet prod cutover — complete as of #611)
  P₂ := Phase 2 (voiceCLI Quadlet migration — blocked on this ADR)

P₁ is complete. Lyra runs four Quadlet containers on `lyra.network`: `lyra-hub`, `lyra-telegram`, `lyra-discord`, `lyra-nats` (port 4223, coexisting with host `nats.service` on 4222). The patterns defined here are validated in prod.

P₂ is blocked. voiceCLI is the first project that is not Lyra. It uses NATS (same auth pattern, same nkey convention), has GPU requirements (RTX 3080, CDI validated), and its nkey seeds currently live in `~/.lyra/nkeys/` — a cross-project coupling resolved by this ADR.

## Decision

### D1 — Image registry namespace: project-named, no `roxabi-` prefix

**Chosen:** `localhost/<project>-<service>:latest` for all projects.

**Rationale:** Container images are per-project artifacts, not shared infra. `~/.lyra/` is Lyra's runtime dir; `localhost/lyra-hub:latest` is Lyra's image. The naming follows ownership, not ecosystem branding. The `roxabi-` prefix is reserved for code genuinely extracted as multi-consumer SDKs (`roxabi-nats`, `roxabi-contracts`) — not a registry namespace for per-project container images.

**Supply-chain hardening (from ADR-053 D3):** `localhost/lyra:latest` is a floating tag. A `podman load` of a tampered image silently replaces it. Enforcement pattern:

1. Post-build: `scripts/deploy-quadlet.sh` captures the image ID:
   ```
   podman inspect --format '{{.Id}}' localhost/lyra:latest > .image-digest
   ```
2. Pre-restart: script reads `.image-digest` and compares against the running image ID. Mismatch → abort with diagnostic.

`.container` files retain `Image=localhost/lyra:latest` for ergonomics. The script is the enforcement point; `.image-digest` is added to `.gitignore` (machine-local build state).

### D2 — NATS: per-project during migration, shared at Phase 4

**Chosen:** Each project uses its own NATS container during migration; Phase 4 consolidates onto shared NATS.

**Rationale:** Shared NATS from day one blocks P₂ on Phase 4 work. Per-project NATS lets voiceCLI proceed immediately. The consolidation path is bounded: update N env files, restart N containers, verify connectivity.

**Topology during migration:**

| Instance | Port | Scope |
|---|---|---|
| Host `nats.service` | 4222 | TLS, system NATS (supervisord-managed projects not yet migrated) |
| `lyra-nats.container` | 4223 | Lyra Quadlet NATS |
| `voicecli-nats.container` | 4224 | voiceCLI Quadlet NATS |
| Subsequent projects | 4225+ | Increment |

**4223 → 4222 consolidation path (Phase 4):**

1. **Prepare auth.conf:** assemble merged auth.conf from all projects' nkey identities. Dry-run validate: `nats-server --config lyra/deploy/nats/nats.conf --signal reload=dry`.
2. **Update env files:** each NATS-using project changes `NATS_URL` to `tls://lyra-nats:4222` on `roxabi.network`. Commit but do not deploy.
3. **Stop host NATS:** `sudo systemctl disable --now nats.service`. All NATS-using projects briefly offline.
4. **Start shared Quadlet NATS:** `systemctl --user start nats.service` — binds 4222. Verify: `ss -tlnp | grep 4222`.
5. **Restart containers one by one** with updated env files. Verify per project.
6. **Retire per-project `nats.container` units.**

**TLS:** shared Quadlet NATS reuses host certs from `/etc/nats/certs/` via volume mount — no regen.

**Auth.conf during migration:** each project's per-project NATS authorizes only its own nkey identities. Cross-project authorizations persist on Lyra's NATS until Phase 4 (voiceCLI workers publish `lyra.voice.*` subjects).

### D3 — Podman network: shared for NATS-communicating projects, isolated for HTTP-only

**Chosen:** Topology matches communication intent.

| Project class | Network | Rationale |
|---|---|---|
| NATS-using: lyra, voiceCLI, roxabi-vault (if daemonized) | `roxabi.network` (Phase 4) | Must reach shared NATS |
| HTTP-only: forge, intel, idna, live, litellm | `<project>.network` | No inter-project networking needed; isolation is free |
| Monitoring (uptime-kuma) | `monitoring.network` | Probes health endpoints |

**Migration window:** projects keep per-project network until Phase 4. Lyra currently uses `lyra.network`; voiceCLI will use `voicecli.network`. Both join `roxabi.network` at Phase 4.

### D4 — Env file convention: `~/.<project>/env/<service>.env`

**Chosen:** Per-project runtime dir matches existing precedent (`~/.lyra/` established for `auth.db`, `keyring.key`, `config.db`, `nkeys/`, `agents/`).

**Credential model (from ADR-054):** Bot tokens are Fernet-encrypted in `~/.lyra/config.db` (table `bot_secrets`) and decrypted via `~/.lyra/keyring.key` using `LyraKeyring`. Adapters do NOT read `TELEGRAM_TOKEN`/`DISCORD_TOKEN` from environment.

**Env file scope:**
- `hub.env`: contains only `LYRA_HEALTH_SECRET` and `LYRA_HEALTH_PORT`
- `telegram.env`, `discord.env`: **deleted** — no env vars needed; tokens come from `config.db`

**Data volume = bind-mount (from ADR-054 D1):**

```ini
[Volume]
Type=none
Device=%h/.lyra
Options=bind
```

Rationale: every credential and store lives in `~/.lyra/`. Bind-mount exposes `config.db`, `keyring.key`, `auth.db`, agent directories without provisioning step.

**UID model: `UserNS=keep-id` (from ADR-054 D2):**

`User=lyra` (UID 1500) is removed from `.container` files. `UserNS=keep-id` maps container UID to host UID (1000, `mickael`). Container processes see themselves as UID 1000 and own all files in `~/.lyra/`.

**Defense-in-depth retained:** `NoNewPrivileges=true`, `ReadOnly=true`, `DropCapability=all`.

**Adapter mounts:** `:ro,z` → `:z` (read-write). Adapters write `discord.db`, `message_index.db`, `auth.db`.

**Podman secrets for nkey delivery (from ADR-054 D5):**

Single-file `.volume` units trigger Podman's loop-device code path (fails). Nkey seeds delivered as Podman secrets:

```sh
podman secret create voicecli-nats-tts ~/.voicecli/nkeys/voice-tts.seed
```

Container references:
```
Secret=voicecli-nats-tts,type=mount,target=/etc/nats/nkeys/voice-tts.seed
```

Benefits: no host paths in unit files; rotation is `podman secret create --replace` + restart; `podman secret ls` provides audit surface.

**`config.toml` — inline bind-mount:**

```ini
Volume=%h/.lyra/config.toml:/app/config.toml:ro,z
```

NOT wrapped in `.volume` unit (single-file bind-mounts fail). `lyra-config.volume` removed.

**nkey seed migration (voiceCLI Phase 2):**

```sh
mkdir -p ~/.voicecli/nkeys/
mv ~/.lyra/nkeys/voice-tts.seed ~/.voicecli/nkeys/
mv ~/.lyra/nkeys/voice-stt.seed ~/.voicecli/nkeys/
# Update voiceCLI auth.conf; reload host NATS
```

### D5 — Deploy script: shared library in `lyra/scripts/deploy-lib.sh`

**Chosen:** Shared shell library in Lyra repo, installed at bootstrap time.

**Versioning:** Each project's `make quadlet-install` copies `deploy-lib.sh` to `~/.local/lib/roxabi/deploy-lib.sh`, pinning commit hash:

```sh
# deploy-lib.sh — installed from lyra @ <commit-sha>
# DEPLOY_LIB_VERSION=1.0.0
```

Downstream scripts source the installed copy, not Lyra's checkout:

```sh
PROJECT=voicecli
CONTAINERS="voicecli-tts voicecli-stt voicecli-nats"
IMAGE="localhost/voicecli:latest"
SECRETS_DIR="$HOME/.voicecli/nkeys"
source "${LYRA_DEPLOY_LIB:-$HOME/.local/lib/roxabi/deploy-lib.sh}"
run_deploy "$@"
```

**Interface stability:** Breaking changes bump `DEPLOY_LIB_VERSION` (semver major); downstream projects run `make quadlet-upgrade-lib`.

#### CI Workflow (from ADR-056)

**Reusable GHA workflow:** `Roxabi/.github/.github/workflows/publish-container.yml`

**Tag strategy:** Release-please emits component-prefix tags (`lyra/v0.3.0`). Workflow strips prefix for semver:

```yaml
- name: Strip component prefix
  run: echo "VERSION=${TAG#lyra/}" >> $GITHUB_ENV
```

**SHA pinning:** All actions SHA-pinned with Renovate config for automated refresh. Floating major tags (`@v4`) rejected on workflows with org-wide `packages: write`.

**Secret scoping:** Callee uses only built-in `GITHUB_TOKEN`. No `secrets: inherit` (over-scopes as Lyra's secret surface grows).

**Makefile hygiene:** Separate local build tag from registry name:

```makefile
LYRA_IMAGE ?= localhost/lyra:dev      # local build
GHCR_IMAGE ?= ghcr.io/roxabi/lyra     # registry
```

**Split metadata/push steps:** Guard with step-level `if:` conditions to avoid emitting all tags on staging pushes.

### D6 — Upgrade coordination: independent releases; batch only for shared-infra changes

**Chosen:** Default independent; coordination triggered by specific events.

| Event | Required action |
|---|---|
| Shared NATS auth.conf change | All NATS-using containers restart after auth reload |
| Phase 4: shared NATS deploy | All NATS-using projects update `NATS_URL` and restart |
| `roxabi.network` creation/renaming | All projects on shared network update `Network=` |
| NATS contract version bump | Per ADR-049 protocol |
| Breaking change to `deploy-lib.sh` | Bump `DEPLOY_LIB_VERSION`; notify downstream |

Everything else deploys independently.

---

### D7 — Home for shared infra: Lyra repo is the home

**Chosen:** Lyra repo hosts shared infra units.

**Rationale:** Lyra is the ecosystem origin. NATS server config, auth.conf, nkey issuance, Quadlet patterns, deploy scripts exist because Lyra needed them. Creating `roxabi-infra` adds repo setup overhead with no functional benefit.

**Lyra repo holds:**
- `deploy/quadlet/nats.container` (Phase 4 shared NATS unit)
- `deploy/quadlet/roxabi.network` (shared Podman network)
- `scripts/deploy-lib.sh` (shared deploy library)
- `docs/architecture/adr/` — cross-project infra ADRs

## Tier Strategy (from ADR-053 D1)

| Tier | Runtime | Entry point |
|---|---|---|
| Dev | Single process, embedded NATS | `lyra start` |
| Simple prod | supervisord + 3 host processes + host `nats.service` | `scripts/deploy.sh` |
| Advanced prod | Podman Quadlet, 4 rootless containers on `lyra.network` | `scripts/deploy-quadlet.sh` |

**Quadlet is the strategic target** for every roxabi project on M₁. Supervisord retires when the last project migrates — triggered by ecosystem readiness, not calendar date.

**Migration order:**

| Project | Status |
|---|---|
| `lyra` | Complete (Phase 1) |
| `voiceCLI`, `imageCLI`, `llmCLI`, `2ndBrain` | Next wave |
| `idna`, `roxabi-forge`, `roxabi-intel`, `roxabi-live` | Deferred |

## Consequences

### Positive

- Seven design questions closed — Phase 2 unblocked.
- Per-project NATS during migration: voiceCLI can proceed immediately.
- Supply-chain hardening: digest pinning detects tampered images before restart.
- `UserNS=keep-id` is the standard UID model — no per-project experimentation.
- Podman secrets for nkeys: no host paths in unit files; audit surface via `podman secret ls`.
- Shared deploy library prevents N-way divergence.
- SHA-pinned CI actions with Renovate automation.
- Secret scoping minimal-privilege from start.
- Lyra's role as ecosystem infra home explicit.

### Negative

- Phase 4 migration step exists for every NATS-using project.
- Downstream projects sourcing `deploy-lib.sh` introduces path dependency. Mitigation: installed copy at bootstrap.
- SHA-pinning adds maintenance burden (Renovate config required).
- Per-project NATS during migration: auth.conf duplication in interim.

## Alternatives Considered

### Alt-A: Shared NATS from day one (D2 Option B)

**Rejected:** Requires Phase 4 topology and merged auth.conf ready before voiceCLI can start. Per-project NATS lets P₂ proceed immediately.

### Alt-B: All projects on one `roxabi.network` immediately (D3 Option A)

**Rejected:** HTTP-only projects have no reason to share network with NATS-using projects. Unintended cross-project communication surface.

### Alt-C: Env files centralized under `~/.roxabi/env/` (D4 Option B)

**Rejected:** `~/.lyra/` is established runtime root. Audit benefit achievable with `ls ~/.*env*` or `make env-audit`.

### Alt-D: Create `roxabi-infra` repo for shared infra (D7 Option C)

**Rejected:** Lyra created the patterns and hosts the ADRs. Downstream dependency on Lyra's repo is an accurate expression of origin role.

### Alt-E: Merge CI workflow as-is, fix findings post-adoption

**Rejected:** Three blocking defects (semver tag parsing, floating action SHAs, undefined `${{ }}` evaluation) would be inherited by every adopter. Fixing once in reference implementation costs less than retroactive patching.
