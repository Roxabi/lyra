## Problem

`deploy/nats/acl-matrix.json` has no lifecycle field on identity blocks. When a NATS identity must be retired (as happened with `tts-adapter` and `sst-adapter` in #690), there are only two manual options: leave the entry in place so credentials keep accumulating on every `gen-nkeys.sh --regenerate` run, or delete it outright with no audit trail and a dangling seed file on disk. Neither path is tooling-enforced.

The consequence is a silently growing security surface: any identity left in the JSON continues to receive ACL grants and fresh NKey seeds on every regeneration, even if the corresponding service no longer exists. The comment at line 286 of `gen-nkeys.sh` — noting that `tts-adapter`/`sst-adapter` were "retired in #690 and removed" — is evidence of the problem: the only record of that retirement decision is a code comment.

## Who

- **Primary:** operator running `gen-nkeys.sh` — needs to retire an identity without deleting its audit record or expanding the live credential set.
- **Secondary:** security reviewer auditing the ACL matrix — needs a machine-readable signal distinguishing active from retired identities.

## Constraints

- `gen-nkeys.sh` must remain backward-compatible: existing callers (CI, setup.sh) pass no new flags; retiring an identity is done by editing `acl-matrix.json`, not by a new CLI argument.
- The CI check must be additive to `check-acl-matrix-spec.sh` or a separate step — it must not require changes to the existing spec sentinel block in `706-per-role-nkeys-acls-spec.mdx`.
- No new external dependencies (no Python, no npm): the CI check uses `jq` + bash, consistent with the existing check.
- Retired identities must remain in `acl-matrix.json` (¬delete) to preserve the audit record.

## Out of Scope

- Automatic deletion of seed files on retirement — out of scope; operator handles seed rotation separately.
- UI or CLI command for retirement — the retirement path is editing the JSON directly; tooling enforcement is via CI.
- Migrating `tts-adapter`/`sst-adapter` back into the JSON as `retired` — they were already removed in #690; this issue covers identities that exist today and may retire in the future.
- Changes to `render_auth_conf` logic beyond the `status` skip — no other ACL semantics change.

## Complexity
