## Source

> "On a un sujet de tools sur lyra. Il faudrait qu'on dégage un pattern, une structure, quelque chose d'assez universel… On aura des tools qui seront internes dans le harness et des tools qui sont externes. Donc comment on va gérer ces cas là ? Sachant que globalement le harness il est fort probable qu'on ait un template de harness mais qu'à chaque fois qu'on appelle un agent différent, l'agent il va spawn sûrement un conteneur différent sur la base de ce harness."
>
> — Trigger of the design session, 2026-05-27

This document captures the full design synthesis from 5 internal/external research agents + 3 domain reviewers (architect, devops, axial-adr-review). It is the **reference articulation** for the tool layer across Lyra and satellites. Companion to `harness-epic-consolidated.md`.

## 1. Context — the scattered state

The "tool" concept is currently split across **four parallel design spaces** that do not yet converge:

| Space | Where | Owns |
|---|---|---|
| **A. Tool registry (LLM-facing)** | epic #493 + #477 + #478 | `ToolHandler` Protocol, `ToolRegistry`, 3 built-ins (`shell_sandboxed`, `file_read`, `web_fetch`), Plugin SDK |
| **B. Worker fleet (job-facing)** | epic #1044 + #1047 + #1052 | `JobHandler` Protocol, atomic/composite distinction, `invoke_subjob` (depth≤3), `--role` workers |
| **C. Harness runtime** | `harness-epic-consolidated.md` (not yet opened as GH epic; supersedes #633 + #987) | Agentic turn loop, tool executor, turn-local working memory, `HarnessRequest`/`HarnessResponse` |
| **D. Satellite ecosystem** | imageCLI, voiceCLI, llmCLI, Postiz, XCLI | NATS workers + CLIs + Quadlet sidecars + per-component NKey secrets |

**The drift signal**: space A defines `ToolHandler`. Space B defines `JobHandler`. Both target NATS dispatch. Both have a registry. **Neither references the other.** The harness consolidated doc (§6, Q1) explicitly flags this as unresolved.

**The user-intent signal** (verbatim from `harness-epic-consolidated.md` §6): *"We will have internal tool and tool used through NATS. Protocol will be likely different because we may use a pre existing tool for harness that might have plugins."* Confirmed user intent, not formalized.

## 3. External SOTA — convergent patterns

Research across LangChain, LangGraph, smolagents, CrewAI, AutoGen, Pydantic AI, OpenAI Agents SDK, Anthropic Tool Use + Skills, MCP. **Six points of convergence** (≥6 frameworks agree):

| Convergent pattern | Status in #493 |
|---|---|
| JSON Schema = universal contract | ✅ |
| Dot-namespaced names | ✅ |
| Sync + async execution pair | ⚠ async-only mandated; Hermes uses sync bridge — re-arbitrated to async-only |
| Rich description ≥ schema for LLM UX | ✅ |
| Registration = list at agent init | ✅ |
| Input examples (Anthropic `input_examples`) | ❌ — to add |
| Behavioral annotations (`read_only`, `idempotent`, `destructive`, `open_world`) | ⚠ only `read_only` — extend |

**Dispatcher uniformity (key architectural choice)**:

| Framework | Built-in vs external dispatcher | Verdict |
|---|---|---|
| Claude Code | **Uniform** (deny-first pipeline, `assembleToolPool()`) | ⭐ adopt |
| smolagents | **Uniform** | ⭐ adopt |
| LangGraph DeepAgents | Graph-uniform | OK |
| OpenAI Codex CLI | **Branched** (built-ins sandboxed, MCP self-responsible) | reject |
| OpenAI Agents SDK | Explicitly branched | reject |

→ **Adopt uniform dispatcher** (one ACL pipeline, same `ToolResult`, transport varies). This is also the axial-correct shape (single dispatcher = single stage primitive, no per-tool reimplementation).

**Per-agent containerization patterns**:

| Pattern | Examples | Tradeoff | Fit for Lyra |
|---|---|---|---|
| A. Python objects in one process | LangGraph, CrewAI, smolagents | No isolation; fast | ❌ no isolation |
| B. Managed cloud containers per session | Anthropic Managed Agents, E2B, Modal | Strong isolation; startup latency | ❌ external infra |
| C. **Quadlet `@` instance templates** | `foo@<inst>.container`, EnvFile per instance | Same image, per-agent identity, ~1-3s start | ⭐ ideal fit |
| D. Shared pool + identity in payload | Current lyra-clipool | Minimal; context leakage risk | partial — fine for hub, not for harness |

→ **Adopt Pattern C** for the harness (`lyra-agent@<slug>.container`). User intuition correct, Quadlet native support.

**Atomic vs composite — 4-layer canonical taxonomy** (derived from Anthropic Skills + smolagents managed_agents + LangGraph subagents + Pydantic AI toolsets):

| Layer | Name | Definition | Frameworks |
|---|---|---|---|
| L0 | **Atomic tool** | Single LLM `tool_use` → single primitive op | All |
| L1 | **Macro** | Deterministic chain of L0, no sub-LLM | smolagents code-agent, lyra `JobHandler` composite (#1052) |
| L2 | **Skill** | Instruction-layer composite — guides LLM via SKILL.md, prompt injection | Anthropic Skills (Oct 2025), Hermes SKILL.md |
| L3 | **Sub-agent** | Recursive harness call, isolated context | Claude Code Task tool, smolagents ManagedAgent, LangGraph subagents |

## 5. Worker ≠ Tool — distinction resolved

User question: "Est-ce qu'on considère les workers comme des tools, un bundle de tools, ou quelque chose d'indépendant qui va utiliser les autres tools ?"

**Answer**: A worker is **not** a tool. A worker is a service that **exposes** tools.

| | Worker | Tool |
|---|---|---|
| Nature | Long-running NATS service | Surface of invocation visible to LLM |
| Deployment unit | Quadlet `.container` | Entry in `ToolRegistry` |
| Cardinality | 1 worker → N tools | 1 tool → 1 endpoint (atomic) or 1 macro (composite) |
| Identity | NATS account + NKey | Dot-namespace in registry |
| Discovery | `$SRV.PING` on boot | `$SRV.INFO` metadata fetch |

**Examples**:

| Worker | Tools it exposes |
|---|---|
| `imageCLI` (Quadlet `imagecli-gen`) | `image.generate`, `image.list_engines`, `image.cancel` |
| `voiceCLI` STT (`voicecli-stt`) | `voice.stt`, `voice.list_models` |
| `voiceCLI` TTS (`voicecli-tts`) | `voice.tts`, `voice.list_voices` |
| `llmCLI` worker | `llm.generate` (atomic), `llm.lifecycle.swap` (control plane) |
| `lyra-vault-intel` (planned, #1050-1052) | `vault.add` (L0b atomic), `vault.add_from_url` (L1 composite — calls `scrape`+`llm.summarize`+`vault.add`) |
| `postiz` (no Quadlet — bash CLI direct from hub) | `postiz.create_post`, `postiz.list_integrations`, `postiz.analytics` |
| `xcli` (no Quadlet — bash CLI direct from hub) | `xcli.post`, `xcli.feed`, `xcli.search` |

→ The harness sees `image.generate` and `bash` identically in its `tools[]` array. Transport difference is invisible to the LLM.

## 6. Bridging #493 ↔ #1047 — the unified registry

`ToolHandler` (#493) and `JobHandler` (#1047) are converging on the same shape. **Bridge them via `roxabi-contracts/tools/`** (axial-adr-review verdict: drift present, refactor before commit).

```python
# roxabi-contracts/tools/protocols.py

class InProcessTool(Protocol):
    """L0a — built-in, compiled in harness binary."""
    name: str                           # dot-namespace (e.g. "bash", "gh.list_prs")
    description: str
    input_schema: dict                  # JSON Schema (portable)
    input_examples: list[dict]          # ≥2 examples (Anthropic convention)
    hints: ToolHints                    # read_only / idempotent / destructive / open_world
    requires_env: list[str]             # ["GH_TOKEN", ...]
    max_result_size_chars: int          # output budget
    async def execute(self, input: dict) -> ToolResult: ...

class RemoteTool(Protocol):
    """L0b — NATS sidecar, plus L1 composite via #1052 invoke_subjob."""
    name: str
    description: str
    input_schema: dict
    input_examples: list[dict]
    hints: ToolHints
    nats_subject: str                   # "lyra.image.generate.request"
    queue_group: str                    # "IMAGE_WORKERS"
    heartbeat_subject: str              # "lyra.image.heartbeat"
    timeout_ms: int = 30_000
    # `check_fn` available via $SRV.PING liveness check (no per-tool callable needed)
    # execute() is implemented by the SDK NATSMicroAdapter, not per-tool

class ToolResult:
    """Discriminated union, mapped to existing WorkerError codes at boundary."""
    # variant: Ok(payload: str)
    # variant: RetryableError(reason: str, retry_after_ms: int | None)
    # variant: TerminalError(reason: str, code: WorkerError.Code)
```

**JobHandler (#1047) becomes a specific case of `RemoteTool`** — the `invoke_subjob` capability is exposed at the worker layer (worker-side composition) and surfaces upward as a single `RemoteTool` to the harness. Depth≤3 enforcement stays in the worker, transparent to the harness.

## 7. Manifest standard — `tool-manifest.toml`

One manifest per repo (lyra has multiple). Single parser in `roxabi-contracts/tools/manifest.py`. Single validator (Pydantic).

```toml
# Per-repo example: imageCLI/tool-manifest.toml

[meta]
name        = "imagecli"
version     = "0.1.1"            # matches pyproject
uid         = 1503
worker_role = "image-worker"     # references hosts.toml role

[invoke]
transport  = "nats"              # "nats" | "http" | "stdio"
cli_bin    = "imagecli"          # entrypoint for direct CLI mode (Postiz/XCLI)

[[tools]]                        # one or more tools exposed by this worker
name              = "image.generate"
description       = "Generate an image from a text prompt using FLUX engines."
nats_subject      = "lyra.image.generate.request"
queue_group       = "IMAGE_WORKERS"
heartbeat_subject = "lyra.image.heartbeat"
request_schema    = "schemas/image_generate_request.json"
response_schema   = "schemas/image_generate_response.json"
examples_file     = "schemas/image_generate_examples.json"
timeout_ms        = 120_000
max_result_size_chars = 4_000    # blob ref, not blob itself
hints             = { read_only = false, idempotent = false, destructive = false, open_world = false }

[[tools]]
name              = "image.list_engines"
description       = "List available image generation engines and their status."
nats_subject      = "lyra.image.engines.list"
queue_group       = "IMAGE_WORKERS"
heartbeat_subject = "lyra.image.heartbeat"
hints             = { read_only = true, idempotent = true }

[data]
data_dir   = "~/.roxabi/imagecli"
volumes    = [
  "~/.cache/huggingface:/home/imagecli/.cache/huggingface",  # shared_ro
  "~/.roxabi/imagecli:/home/imagecli/.roxabi/imagecli",       # tool_data
]

[deploy]
quadlet_dir  = "deploy/quadlet"
components   = ["gen"]
env_dir      = "~/.roxabi/imagecli/env"

[auth]
nats_account     = "image-worker"     # references hosts.toml
nkey_secret_name = "imagecli-nats-gen"
nkey_env         = "NATS_NKEY_SEED_PATH"
```

**Postiz / XCLI variant** — `transport = "stdio"` or `transport = "http"`, no `nats_subject`, no Quadlet sidecar. The harness invokes the CLI directly (devops verdict — no value in wrapping bash in NATS Micro for low-frequency calls).

## 8. Identity, auth, volume — formalized standard

| Concern | Standard | Source |
|---|---|---|
| **NATS account** | One per role (`lyra-hub`, `voice-worker`, `image-worker`, `llm-worker`) | Existing, in `hosts.toml` |
| **NKey credential** | One Podman secret per component (`voicecli-nats-tts`, etc.) | Existing |
| **UID anchor** | Fixed UID per tool (image=1503, voice=1501, llm=1502) | Existing |
| **EnvironmentFile** | `%h/.roxabi/<tool>/env/<role>.env` | Ratified `feedback_quadlet_env_in_tool_data_dir.md` — universalize to imageCLI, voiceCLI |
| **Shared volumes** | `~/.cache/huggingface` (RO, multi-tool) | Existing |
| **Tool data volume** | `~/.roxabi/<tool>/` (RW, single-tool) | Existing (voiceCLI grandfathered at `~/.voicecli/`) |
| **Per-agent volume** | `~/.roxabi/<tool>/agents/<agent-id>/` subdir inside bind-mount | NEW — devops verdict: subdir, not named volumes (Syncthing) |
| **Agent identity propagation** | `agent_id` field embedded in JSON payload body of every NATS request | NEW — single site in `roxabi-tools-sdk` (`AgentIdMiddleware`); breaking-change ADR on `roxabi-contracts` |
| **Identity enforcement** | ACL at harness pool-assembly time (deny-first); tools log `agent_id` for audit only | NEW — Claude Code pattern |

**Rejected**:
- Account-per-agent at scale (≤10 agents foreseeable — disproportionate operational surface)
- NATS protocol header for `agent_id` (requires transport-layer changes; embed in JSON payload instead)
- Named volumes (break Syncthing M₁↔M₂ replication)
- OCI artifact distribution via ORAS (no consumer; revisit only at pull-CD adoption)

## 9. Reviewer findings — synthesized

### 9.1 Architect (verdict: MODIFY)

| Finding | Decision |
|---|---|
| `RemoteToolHandler extends ToolHandler` is Liskov violation | ✅ Use 2 distinct Protocols (`InProcessTool` + `RemoteTool`) |
| Hermes sync-bridge is acknowledged tech debt — don't bring forward | ✅ async-only `execute()` for in-process tools; remote tools handled by SDK |
| `execute() → str` loses retry semantics | ✅ Return `ToolResult` discriminated union; serialise at LLM boundary |
| `$SRV.PING` enumeration thundering-herd at 20 tools | ✅ Reuse lyra `WorkerRegistry` heartbeat-TTL pattern instead |
| Schema as Pydantic class blocks JS/Rust agents | ✅ JSON Schema in manifest is SSoT; Pydantic only inside hub |
| `tool-manifest.toml` should NOT block #477 | ✅ #477 stays in-code registration; manifests appear in #478 |

### 9.2 DevOps (verdict: 7 specific calls)

| # | Question | Verdict |
|---|---|---|
| 1 | NATS account vs ACL for multi-agent | **Header-only via JSON body** — current account-per-role is right granularity |
| 2 | Per-agent volume namespacing | **Subdir bind-mount** `~/.roxabi/<tool>/agents/<agent-id>/` (Syncthing-safe) |
| 3 | voiceCLI `~/.voicecli/` migration | **Keep grandfathered** — manifest allows `tool_data` override |
| 4 | OCI artifact distribution via ORAS | **Defer** — no consumer |
| 5 | Quadlet sidecar for Postiz/XCLI | **No** — bash CLI direct from hub for ≤10 agents. Postiz token migrates to `env/postiz.env` (security fix, independent) |
| 6 | EnvironmentFile universalization | **Yes**, low-risk for imageCLI/voiceCLI |
| 7 | Hub currently propagates agent identity? | **No** — codec-layer change required (single site in SDK) |

### 9.3 Axial-ADR-Review (verdict: DRIFT PRESENT, refactor before commit)

ADR-073 primary axis = `stage` (pipeline slice). The 5 tools sit on non-primary axis (platform/adapter).

| Finding | Class | Solution |
|---|---|---|
| Quadlet boilerplate + NATS Micro adapter duplicated across 5 tools | `target-axis-trap` (blocking) | Extract `roxabi-tools-sdk` + `roxabi-contracts/tools/` (single canonical impl) |
| `X-Roxabi-Agent` propagation per-tool = textbook N×M on security-bearing concern | `target-axis-trap` (blocking) | Single site in `roxabi-tools-sdk` SDK transport layer; **breaking-change ADR on `roxabi-contracts` required** |
| `tool-manifest.toml` parser duplicated per tool | partial trap | Single parser in `roxabi-contracts/tools/` |
| `RemoteToolHandler` location | dependency direction risk | Place in `roxabi-contracts/tools/`, not lyra core (satellites import contracts, never lyra) |
| Per-agent dir creation logic | minor | Shared helper in SDK |

## 14. Glossary

| Term | Definition |
|---|---|
| **Harness** | The agentic control loop — owns turn loop, tool dispatch, turn-local memory. One binary, N Quadlet instances. |
| **Tool** | Surface of invocation visible to the LLM. Has name, description, schema, examples, hints. Either L0a (built-in), L0b (NATS), L1 (macro), L2 (skill), or L3 (sub-agent). |
| **Worker** | A long-running NATS service that exposes one or more tools. Not a tool itself. |
| **Atomic tool** | Single LLM `tool_use` → single primitive op. No internal LLM loop. |
| **Composite tool** | One callable from LLM perspective; internally chains multiple primitives. Macro (L1) = deterministic chain; Skill (L2) = LLM-guided; Sub-agent (L3) = recursive harness. |
| **Built-in tool** | Compiled in the harness binary; in-process; always available; no `$SRV.INFO` discovery. |
| **External tool** | NATS sidecar with `$SRV.INFO` discovery + heartbeat. Or `transport = "stdio"|"http"` for direct CLI wrapping. |
| **Skill** | Instruction-layer composite. SKILL.md (Anthropic Oct 2025 convention) injected into system prompt to guide LLM through a sequence of L0/L1. |
| **Sub-agent** | Nested harness invocation with isolated context. Called via Task tool from parent harness. |
| **Agent** | A configuration profile (system prompt + allowed tools + persona). Materialized as one `lyra-agent@<slug>.service` instance. |
| **Pattern C** | Quadlet `@` template instantiation — one image, N per-instance configs via EnvironmentFile + volumes. |
| **Uniform dispatcher** | One ACL pipeline, one `ToolResult` type, transport-agnostic. Claude Code / smolagents pattern. |
| **roxabi-tools-sdk** | New package — transport primitives (NATS Micro adapter, identity middleware, registry client). |
| **roxabi-contracts/tools/** | New submodule — shared Protocols (InProcessTool, RemoteTool), shared types (ToolResult, ToolHints, ToolManifest). |
