## Consensus

### F1 — voice-client absent from auth.conf

**ρ: Apply — run gen-nkeys.sh (Solution 1)**
**Confidence: high | Vote: 2-0 (tester abstained)**

The committed `auth.conf` is a template (line 1: `# TEMPLATE — DUMMY KEYS — NOT FOR PRODUCTION`). Production NATS runs from a Podman secret generated by `gen-nkeys.sh --regen-authconf` on the host. The fix has two parts:

1. **Committed template:** run `./deploy/nats/gen-nkeys.sh --template-only` and commit the result so the template reflects all 10 identities (currently 9 — voice-client absent).
2. **Production:** run `sudo ./deploy/nats/gen-nkeys.sh --regen-authconf` after this PR merges, then `make quadlet-secrets-install && podman kill -s HUP lyra-nats`.

Manually editing auth.conf (Solution 2) violates ADR-046 Invariant 1 — auth.conf must always be the rendered output of acl-matrix.json. The next gen-nkeys.sh run would silently overwrite any manual edits.

**Operational risk if deferred:** voice-client connects but nkey rejected → dictation feature silently broken from day one in production.

### F2 — test_idempotent_second_call state leak

**ρ: Apply — add `kv.purge("hub.ready")` before test (Solution 1)**
**Confidence: high | Vote: 2-1 (architect dissent recorded)**

`nats_server_jetstream_url` is session-scoped — the `lyra-state` bucket and `hub.ready` key from `test_writes_hub_ready_key` persist into `test_idempotent_second_call`. The current `entry.value == b"true"` assertion would pass even if `announce_hub_ready()` was a no-op, because the key was already written by a prior test.

Fix: add purge at test start, matching the pattern already applied to `test_timeout_returns_false_and_warns`.

**Architect dissent:** `assert entry.revision > 1` is equally valid and provides a tighter semantic proof. Majority accepted that revision assertion tests NATS internals rather than the function contract; purge is the canonical KV isolation pattern for this test suite.

### F3 — test_none_sentinel_skipped not discriminating

**ρ: Apply — remove test (Solution 2)**
**Confidence: high | Vote: 2-1 (architect dissent recorded)**

The test is structurally identical to `test_wait_for_hub_watch_path`: both start the probe, write `hub.ready` after a delay, assert `result is True`. The None sentinel (`if entry is None: continue`) is not deterministically observable through the public API in integration tests — whether it appears depends on whether the bucket exists when `kv.watch()` is called.

Additionally, log coverage for `"Hub ready (KV watch)"` already exists in another test. No unique regression value.

**Architect dissent:** wanted to keep with a caplog assertion for `"Hub ready (KV watch)"`. Majority accepted that this log assertion already exists elsewhere, making the test fully duplicate.

### F4 — nats_server_jetstream_url fixture duplication

**ρ: Defer**
**Confidence: high | Vote: 2-1 (tester dissent recorded)**

Two ~30-line near-identical session-scoped fixtures (with/without `--jetstream`). Extracting `_spawn_nats_server(*flags)` is the right long-term pattern but carries no production risk and no urgency.

**Tester dissent:** bug fixes or improvements to the startup loop must be applied twice; extract now to prevent future divergence. Majority accepted that the duplication is localized and conftest.py readability benefit outweighs the DRY concern at current scale. Revisit if a third variant is needed.

### F5 — asyncio.timeout 3.11+ check

**ρ: No action — non-issue**
**Confidence: high | Vote: 3-0 unanimous**

`packages/roxabi-nats/pyproject.toml` declares `requires-python = ">=3.12"`. Root lyra declares `requires-python = ">=3.12,<3.13"`. `asyncio.timeout()` requires 3.11+. Both constraints are strictly above the floor. Production is Ubuntu 26.04 LTS (Python 3.12 native). No change needed.
