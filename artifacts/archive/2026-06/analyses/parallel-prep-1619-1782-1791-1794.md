## 3. Semantic coherence: #1794 vs #1619

**Verdict: Fully coherent. No contradictions.**

Both specs agree on all three pillars of the ratified job-id model:

| Pillar | #1794 (ADR-084 Amendment text) | #1619 (WorkEnvelope spec) | Match? |
|---|---|---|---|
| `job_id = run` | "one entry → full processing → terminal closing message" (Change 4 expansion) | `job_id: str` min_length=1, mandatory on WorkEnvelope; "root `job_id` minted at ingress" (frame :20) | ✓ |
| Internal hops opaque | "Internal worker hops (e.g. cli_pool multi-turn LLM calls) are opaque — they are NOT sub-jobs and carry no new `job_id`" (Change 4) | Not contradicted; #1619 adds `job_id` as a field invariant, not a per-hop counter | ✓ |
| Sub-jobs explicit via `parent_job_id` + `composite_depth ≤ 3` | Amendment table: "Cross-process decomposition … EXPLICIT sub-jobs via `parent_job_id` + `composite_depth ≤ 3`" | `WorkEnvelope.parent_job_id: str \| None = None` (nullable); `composite_depth` already SHIPPED in packages | ✓ |
| Option C unchanged | "#1794 amendment must NOT change Option C: WorkEnvelope/ContractEnvelope split, mandatory `job_id` min_length=1, nullable `parent_job_id` None at root" | WorkEnvelope spec IS Option C | ✓ |

**Direct quotes confirming alignment:**

- #1794 spec line 27: *"Option C (WorkEnvelope/ContractEnvelope split, mandatory `job_id` min_length=1, nullable `parent_job_id` None at root) is **ratified and unchanged** by this amendment."*
- #1619 frame line 21–23: *"a `WorkEnvelope(ContractEnvelope)` subclass carries mandatory `job_id` (`min_length=1`) + nullable `parent_job_id`; infra messages stay on bare `ContractEnvelope`"*

No semantic divergence. #1619 implementer can use the post-#1794 ADR-084 as its canonical reference without risk.
