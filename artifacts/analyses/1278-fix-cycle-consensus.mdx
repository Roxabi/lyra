### Rationale

- **S1 wins majority (2-1)**: security-auditor flags as Low (in-process TOCTOU, not exploitable) but defers to backend-dev. Both impl experts agree the fix is trivial (3 lines) and the race is a real lifecycle hazard on shutdown under active heartbeat traffic. Cost-of-fix << cost-of-defer.
- **S2 unanimous defer**: clean fix requires moving `worker_registry` out of `lyra.nats`, which is structural and crosses Phase 1 boundary. Current `ignore_imports` workaround with DEBT tag is honest.
- **S3 wins majority (2-1)**: codec→client inversion will fail importlinter once `lyra.transport` is layered in Phase 2; better fix now (small) than future regression unpick.
- **S4/S5/S6 win majority (2-1)**: small independent fixes; security has no objection, just no security stake.
- **B5 win majority**: trim image_client via S3 (move ImageGenParams to codec); exempt llm_client (88L borderline) and llm_codec (170L spec-acknowledged for non-trivial wire shape).

### Trade-offs

1. **S1 deferral risk vs. fix complexity** — One-liner fix vs. cryptic NATS errors on shutdown under load. Apply.
2. **S2 importlinter gap vs. scope creep** — DEBT-tracked layer-boundary absence means future code can import `WorkerPoolClient` anywhere without lint failure. Acceptable Phase 1; tracked for Phase 2.
3. **S3 backward-compat shim** — Re-exporting `ImageGenParams` from `nats_image_client.__all__` for callers needs a deprecation comment, else maintainers may repeat the inversion.

## Bonus security concern (preventive follow-up)

`SanitizedError.detail: str | None` field (`src/lyra/transport/_result.py:36`) has no construction-time validator enforcing `type(exc).__name__`-only content. All current callers pass `None`, but a future caller could populate `detail=str(exc)` without any type-check or test failure — silent #1212 regression surface.

**Recommendation:** open a separate issue to either remove `detail` from `SanitizedError` or add a validator mirroring `WorkerError._sanitize_detail`. **Not a merge blocker** — preventive control.
