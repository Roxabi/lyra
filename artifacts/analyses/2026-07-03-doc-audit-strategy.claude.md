**Le rot n'est pas uniforme — il est exactement anti-corrélé aux gates :**

| Zone | État | Pourquoi |

**Leçon systémique** : les docs sains sont ceux écrits *intent-level avec pointeur vers leur SSoT machine* (stack.yml, quadlet.toml, CURRENT.generated, .d.ts). Les docs pourris sont les inventaires hand-maintained (compteurs 9/7/10/16/31 vs réalité 19/13/13/19/36) et les recettes jamais ré-exécutées.

## 4. Stratégie proposée — contrat par couche

Le problème n'est pas le volume, c'est l'absence de **contrat de fraîcheur par couche**. Proposition :

```
Couche 0 — SSoT machine        quadlet.toml · acl-matrix.json · stack.yml · CURRENT.generated.md ·
  (générée/gated)              error-codes.md · flows.json(à gater ou tuer)
                               RÈGLE : tout inventaire/compteur ne vit QU'ici. Ailleurs → pointeur.

Couche 1 — Intent              domain pages docs/architecture/ · réseau AGENTS.md · standards/
  (invariants, ≤350 l.)        RÈGLE : invariants only, ¬compteurs, ¬listes de symboles, ¬file:line ;
                               gated doc_drift. Déjà saine — la préserver, ne pas y déroger.

Couche 2 — Procédures          runbooks/ (fusion ops/) + onboarding (QUICKSTART/GETTING-STARTED) +
  (commandes exactes)          CONTRIBUTING + plugins ops
                               RÈGLE : seule couche autorisée à citer des commandes exactes → chaque
                               doc doit être soit smoke-testé, soit gated, soit daté. Un runbook
                               faux est pire que pas de runbook.

Couche 3 — Résidu              artifacts/ (specs/plans/frames/analyses) + history/ + ADR archive
  (traçabilité)                RÈGLE : lifecycle lié à l'issue (close → archivable) ; JAMAIS de
                               « current truth » ici (graduation obligatoire vers couche 1) ;
                               git history = archive profonde.
```

### Politique artifacts/ (le vrai gisement : −44 % du markdown)

1. **Graduation obligatoire** : les 3 « current truth » désignés par des ADRs actifs (sentinelle-four-planes-spec, otel-raw-store-spec, ingress-connector-goal) graduent vers les domain pages ; ADR-086 redevient vrai.
2. **Wave d'archive scriptée** à la clôture d'issue (mensuelle), avec étape obligatoire de **réécriture de liens** — la wave 2026-06 a laissé **18 liens morts dont 5+ depuis des ADRs actifs** (071, 075, 079, 083, 087).
3. **HEAD ne garde que la wave courante + précédente** ; les plus anciennes sortent de HEAD (tag tombstone `artifacts-archive/YYYY-MM` + table de correspondance dans un `artifacts/README.md` à créer). Supprimer `archive/2026-06` de HEAD = −44 % du markdown + moins de bruit grep/ccc.
4. **Specs post-merge → corps collé dans l'issue** à la clôture ; `frames/` cesse d'accumuler (100 % d'issues fermées, 0 consommateur).
5. **Sécurité** : retirer `artifacts/{specs,plans,analyses,frames}/` de l'allowlist `.gitleaks.toml:8` (652 fichiers en zone aveugle) — après rotation des exemples réels.
6. **Exceptions permanentes documentées** : `debt/` (registre outillé), `postmortems/`, `TEMPLATE/`.

### Gates — fermer les angles morts sans fatigue

- Préférer **dé-compter** (supprimer les compteurs/inventaires) à sur-gater — les compteurs sont l'angle mort structurel des deux gates ; `check_doc_semantic_drift.py` a déjà un pattern « wrong container counts » mais son scope exclut AGENTS.md racine.
- Ajouter aux patterns semantic_drift les tombstones récurrents trouvés : `make deploy`, `meta.json`, `bot_secrets`, `keyring.key`, `FACTORY_VAULT_DIR`, `gen-nkeys.sh`.
- Les docs onboarding **réécrits** entrent dans le scope `doc_drift` (l'exemption actuelle est exactement ce qui a masqué le rot) ; le fix doc doit être couplé à un smoke du parcours réel (`factory bot init` + `bot secret install` + boot), sinon on documente un deuxième flux mort.
- `check_workflows_snapshot.sh` : câbler en CI ou supprimer la carte (leçon « generated-state gate must block »).

### Séquencement (risques identifiés par la critique)

1. **Lot 0 — vérité d'abord** : les 20 drifts high (§2) se corrigent AVANT tout déplacement. Runbooks d'incident en tête.
2. **Lot 1 — consolidation par lots** avec co-livraison des **consommateurs machine dans la même PR** : `check_volumes_table.sh` parse machinalement la table Volumes de `architecture/deployment.md` (merge-blocking) ; `check_doc_drift.py` liste `QUADLET-DEPLOYMENT.md` nommément ; `stack.yml standards.*` pointe DEPLOYMENT/CONFIGURATION/GETTING-STARTED.
3. **Redirect stubs, pas moves secs** (pattern `OBSERVABILITY.md`, validé) : 9 issues OUVERTES + MEMORY.md + ssot shards + roxabi-plugins pointent des chemins docs/ — « 0 refs » n'a été mesuré qu'in-repo.
4. **Zones chaudes = docs après code** : job-model (chaîne #2142 en vol), ingress. Zones froides = docs immédiat (nkey-rotation, onboarding).
5. **Migration invariant-par-invariant avant archivage** (doctrine v2) — 13 fusions déjà RÉFUTÉES en wave 3 ADR prouvent que les merges « évidents » échouent souvent ; ne pas archiver HAPPY-PATHS (709 l.) sans sweep sole-home.
