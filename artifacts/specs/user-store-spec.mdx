## Problem

`IdentityAliasStore` linked platform keys to a **platform primary** (`tg:user:X`), not to an
internal person id. Grants, prefs, and memory could not key off a stable cross-platform
identifier.

## Decision

Introduce **UserStore** in `auth.db`:

| Table | Role |
|-------|------|
| `users` | Canonical person (`rx:user:<uuid>`) |
| `platform_identities` | `tg:user:…` / `dc:user:…` → `users.id` |

`IdentityAliasStore` becomes a thin facade: `/link` challenges stay; link/unlink/resolve
delegate to UserStore. Legacy `identity_aliases` rows migrate once on connect.

## API

- `resolve_user_id(platform_key) -> rx:user:… | None`
- `resolve_aliases(platform_key) -> frozenset[str]` (backward compatible)
- `link_platform_keys(primary, secondary) -> rx:user:…`
- `ensure_user(platform_key)` — lazy registration at bootstrap seed

## Wiring

- `StoreBundle.user: UserStore`
- Bootstrap: `seed_auth_and_users()` registers owners/admins after trust seed
- `AgentGrantStore.authorize()` expands principals via UserStore (grant on `rx:user:` matches linked platforms)

## CLI

```bash
factory user list
factory user show tg:user:7377831990
factory user show rx:user:<uuid>
```

## Follow-ups

- Grants keyed only by `rx:user:` (drop per-platform duplicates)
- `migrate-bot-grants` seeds agent grants from `rx:user:` principals
- Pairing `/join` writes agent-scoped grants on canonical user
