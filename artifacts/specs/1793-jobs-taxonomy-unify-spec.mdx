## Context
**Promoted from:** [frame](../frames/1793-jobs-taxonomy-unify-frame.mdx)
**GitHub issue:** #1793
**SSoT design doc:** `docs/architecture/job-model.md` (§15.6 unified taxonomy)
**ADR archive (historical only):** `docs/architecture/adr/076-three-nats-planes.mdx` — lines 114, 185, 272 reference old subjects; no gate trigger, no change required.

## Goal

Retire `factory.results.<job_id>` and `factory.progress.<job_id>` as standalone top-level subject families and replace them with `factory.job.<job_id>.result` and `factory.job.<job_id>.progress` (plus new facet helpers for `.steer`, `.opened`, `.closed`) so that `roxabi-contracts` exposes a single unified `factory.job.<id>.*` subject hierarchy before #1812 (OmpWorker) adds real callers.

## Users

- **Contracts maintainer** (this PR's author): performs the mechanical rename within `packages/roxabi-contracts/`.
- **#1812 (OmpWorker) implementer**: consumes the new `jobs_result()`, `jobs_progress()`, `jobs_steer()`, `jobs_opened()`, `jobs_closed()` helpers as its NATS subject source. This issue is a hard prerequisite for #1812.
- **CI**: enforces no-old-literal gate via the success criteria grep check.

## Expected Behavior

After this PR merges:

1. Calling `jobs_result("abc-123")` returns `"factory.job.abc-123.result"` (was `"factory.results.abc-123"`).
2. Calling `jobs_progress("abc-123")` returns `"factory.job.abc-123.progress"` (was `"factory.progress.abc-123"`).
3. Three new helpers are available: `jobs_steer("abc-123")` → `"factory.job.abc-123.steer"`, `jobs_opened("abc-123")` → `"factory.job.abc-123.opened"`, `jobs_closed("abc-123")` → `"factory.job.abc-123.closed"`. All five helpers delegate validation to `validate_job_token()`.
4. `SUBJECTS` (`_Subjects` dataclass) exposes a single `job_prefix: Literal["factory.job"] = "factory.job"` field. The old `result_prefix` and `progress_prefix` fields are removed from the dataclass.
5. `jobs_result` and `jobs_progress` keep their canonical names — only their return values change (no rename, no alias layer). `__all__` in `jobs/__init__.py` continues to export exactly `jobs_result`, `jobs_progress`, plus the three new helpers.
6. `JobProgress` model docstring (line 72 of `models.py`) reads `"Published to factory.job.<job_id>.progress (best-effort)"` instead of the old `factory.progress.<job_id>` string.
7. `jobs/__init__.py` re-exports all five helpers in `__all__`.
8. `README.md` subject table rows for `factory.results.<job_id>` and `factory.progress.<job_id>` are updated to `factory.job.<job_id>.result` and `factory.job.<job_id>.progress`; rows for `.steer`, `.opened`, `.closed` are added.
9. `CHANGELOG.md` gains a new `## [0.10.0]` head entry documenting the subject rename and new helpers.
10. `pyproject.toml` version is bumped from `0.9.0` to `0.10.0`.
11. `docs/architecture/messaging.md` line 128 plain-text reference `factory.progress.<job_id> (#1044, future)` is updated to `factory.job.<job_id>.progress (#1044, #1793)`.
12. **ACL matrix is not touched.** ACL grants for `factory.job.*.*` subjects are #1812's responsibility.
