### Notes
- `type: ignore` comments: 3 found, all defensive (import-untyped for third-party lib, union-attr for NATS sub, no-any-return for NATS metadata). Not flagged as issues.
- Platform-native message types (`aiogram.Message`, `discord.Message`, NATS `Msg`) in inbound handlers and normalize functions are intentionally broad at the boundary layer and are not flagged unless they leak into internal protocol surfaces.
- `agent_cmd` files are clean: all CLI commands have `-> None` annotations, `Any` usage is limited to `dict[str, Any]` for CLI kwargs and `**kwargs: Any` in `_patch`, which is defensible for CLI parameter passthrough.

### Recommendations (prioritized)
1. **Tighten Telegram facade properties** (P1, effort: S) — Replace `Any` on `bot`/`dp` properties with `aiogram.Bot` / `aiogram.Dispatcher` (or `\| None`). These are the most frequently accessed types in the partition.
2. **Type the formatter protocol surface** (P2, effort: S) — Replace `Any` in `send_placeholder`, `edit_placeholder_text`, `send_trace_placeholder`, `render_buttons` in both `TelegramFormatter` and `DiscordFormatter`. These are protocol methods consumed by the outbound emitter; typing them prevents downstream `Any` propagation.
3. **Add return annotation to `_make_verifier`** (P2, effort: XS) — Single line: `-> Callable[[Request], None]`.
4. **Narrow `_make_emitter` callables** (P2, effort: S) — Replace `tuple[Any, ...]` and return `Any` with `tuple[int, int \| None, int \| None]` and `str` for the Telegram path, or use a generic `MetaT` TypeVar if the shape varies by platform.
5. **Parameterize unparameterized dict/list** (P3, effort: XS) — 4 occurrences across `telegram_formatter.py` and `telegram_outbound.py`.
6. **Type Discord voice command handlers** (P3, effort: S) — `discord_voice_commands.py` uses `Any` for 5 parameters that could be `discord.Message`, `discord.Guild`, `discord.Interaction`.
7. **Type NatsOutboundListener in `nats_stream_decoder.py`** (P3, effort: XS) — 4 functions take `listener: Any` instead of `NatsOutboundListener`.
