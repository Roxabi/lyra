### Summary
P5 (Adapters + agent_cmd) shows 1 P1 issue: NatsOutboundListener.stop() cancels stream tasks without awaiting them, risking unhandled exceptions and resource leaks. 3 P2 issues found around blocking I/O in async contexts (subprocess.run, file open, large in-memory buffer writes). 1 P3 informational note about threading.Queue usage in Discord voice. No time.sleep, sync requests, unawaited coroutines, or event loop misuse detected.

### Recommendations
1. **P1 — NatsOutboundListener.stop()**: Add `await asyncio.gather(*self._stream_tasks.values(), return_exceptions=True)` after cancellation before clearing the dict (lines 112-114). This ensures `_drain_stream()` `finally` blocks execute and stream state is cleaned up.
2. **P2 — subprocess.run**: Wrap `_check_secret()` in `asyncio.to_thread()` or switch to `asyncio.create_subprocess_exec()` in `agent_cmd/platforms/_commands.py`.
3. **P2 — file I/O**: Use `aiofiles` or `asyncio.to_thread()` for `config_path.open("rb")` in `agent_cmd/bots/init.py`.
4. **P2 — BytesIO**: For large audio buffers, consider using `asyncio.to_thread()` for `BytesIO.write()`/`read()` in `_shared_audio.py` and `telegram_audio.py`.
5. **P3 — queue.Queue**: Documented intentional pattern. No action needed unless profiling shows event-loop stalls from large queue drains.
